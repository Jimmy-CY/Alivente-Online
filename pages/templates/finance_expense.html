What is an Expense record?

An Expense record is a single budgeted expense for a single property. It's where everything from Configuration finally comes together to describe a real-world cost — for example, "Eleftheroupoleos pays €245 in communal fees every January".

Each Expense record is built from four pieces:

  1. Property — which property this expense belongs to
  2. Expense Line Type — what the expense is (e.g. Property Manager, Communal Fees 1)  →  becomes the row label in the P&L
  3. Expense Type — when it's paid (e.g. Monthly, June, Quarterly)  →  controls which months the amount is counted
  4. Expense Amount — how much (in euros) is paid per active month
Two flavours of Expense record

Most Expenses are standard — one record per property, captured manually. But some are Pro-Rata — one bill split automatically across multiple properties.

  • Standard Expense — e.g. each property pays its own electricity bill at its own amount. Use the Add / Edit (Standard) tab.
  • Pro-Rata Expense — e.g. €3,000 audit fee covers the whole Cyprus portfolio and gets split proportionally across all Cyprus properties. Use the Pro-Rata Capture Flow tab.

Which flow you get is determined by the Expense Line Type you pick — if it has Pro-Rata = Yes, the property selection panel appears automatically.

A worked example

Looking at the table now — Eleftheroupoleos has 8 Expense records, including:

  • Property Manager / Monthly / €52  →  €52 every month, all year
  • Communal Fees 1 / January / €245  →  €245 once per year, in January
  • Communal Fees 2 / July / €210  →  €210 once per year, in July
  • Financials (Cyprus) / June / €293  →  this property's pro-rata share of the annual Cyprus audit fee, paid in June
Where this fits

This is the final piece of the three-part Expense configuration:

  1. Expense Types — when the expense is paid (the months pattern)
  2. Expense Line Types — what the expense is called on the P&L (and whether it's Pro-Rata)
  3. Expenses (this page) — the actual records on each property

If you haven't set up Types and Line Types yet, do those first — the dropdowns on the Add Expense form are populated from them.

Reading the Table

Records are grouped by property in collapsible rows — one row per property, with the records hidden inside until you expand. The layout mirrors the Revenues page exactly.

Property header rows
  •  A chevron arrow on the left — right-pointing when collapsed, down-pointing when expanded.
  • The property name.
  • A teal 8 count badge showing how many Expense records that property has.
Expanding and collapsing
  • Click a property header to expand it. The chevron rotates down and the records appear below.
  • Click the same header again to collapse it.
  • Click a different property's header and the previously-open one auto-collapses — only one property can be open at a time.
Inside each property

Records are sorted alphabetically by Expense Line Type, with five columns:

  • Property — the property name (repeated for clarity).
  • Expense Line Type — the category (e.g. Communal Fees 1, Property Manager).
  • Expense Type — the months pattern (e.g. Monthly, January, Quarterly).
  • Expense Amount — the euro amount per active month, formatted with thousand separators (e.g. € 245, € 1,250).
  • Details — an Edit button to modify that record.
Properties with no Expense records don't appear here. If a property is missing from the list, it currently contributes €0 to the Expenses side of the P&L — click Add New to start populating it.
Adding a Standard Expense

"Standard" means a normal property-specific expense, where each property has its own bill at its own amount — e.g. each property pays its own electricity charge.

Click Add New in the top-right to open the Add Expense form. Four fields in a row:

  1. Property — dropdown of all properties. Pick the one this expense belongs to.
  2. Expense Line Type — dropdown populated from Expense Line Types (e.g. Property Manager, Electricity, Cleaning Costs). Pick a non-Pro-Rata Line Type for the standard flow.
  3. Expense Type — dropdown populated from Expense Types (e.g. Monthly, Quarterly, June).
  4. Expense Amount — the euro amount paid per active month.

Click Save in the top-right and the new record appears in the property's group on the listing page.

The amount is per active month, not per year. If a property pays €52 in monthly Property Manager fees, enter 52 — not 624. The system multiplies by the months your chosen Type marks as active. So €52 paired with Monthly = €624/year, but €245 paired with January = €245/year (one payment).

What if I pick a Pro-Rata Line Type by accident?

If you select a Line Type with Pro-Rata = Yes, the form changes — the Expense Amount becomes auto-filled and locked, and a property selection panel appears below. That's the Pro-Rata flow; switch to the next tab for the full walk-through, or just change the Line Type back to a non-Pro-Rata one.

Editing a Standard Expense

Expand the property's row, then click the Edit button on the relevant record. The form is identical to the Add form, with all four fields pre-filled. Update what you need and click Save.

Edits affect the P&L immediately — including history. Expense records aren't dated — they describe an ongoing pattern. Changing the amount from €52 to €60 instantly recalculates the P&L for every month, every year, including past periods.
Changing the Expense Type clears unused months. If you switch from Monthly to January, the system wipes the amounts from Feb–Dec and only retains January. This keeps the data clean but is irreversible without a manual re-edit.
The Pro-Rata Capture Flow

When you pick an Expense Line Type that has Pro-Rata = Yes, the form switches into a different mode designed to split one bill across multiple properties. Here's the full step-by-step flow.

Step 1 — Open the Add or Edit form

From the listing page, click Add New to capture a new pro-rata bill, or click Edit on an existing pro-rata record to revise the distribution.

Step 2 — Select the four standard fields
  • Property — the property you're capturing the expense for. This will be the "anchor" property in the distribution and cannot be removed from it.
  • Expense Line Type — pick a Pro-Rata Line Type (e.g. Financials (Cyprus)). As soon as you pick it, the form changes.
  • Expense Type — the months pattern for when the bill is paid (e.g. June for an annual audit invoice in June).
  • Expense Amount — auto-filled with the Pro-Rata Amount from the Line Type and locked / greyed out. You cannot override this here — if the bill amount has changed, edit the Line Type's Pro-Rata Amount first, then come back.
Step 3 — The property selection panel appears

A new section titled Select Properties for Pro-Rata Distribution appears below the four fields, with:

  • A Country quick-filter dropdown ("Select Based on Country") — choosing a country auto-ticks every property in that country in one action.
  • A scrollable list of every property, each with a checkbox and the property's Current Value shown in parentheses (e.g. Apolloneon - Demetri (€200,000)).
  • The anchor property is auto-checked and locked — you can't un-tick it because you're capturing the expense for it.

Tick every property the bill should cover. You can:

  • Use the Country filter as a shortcut to tick all (e.g.) Cyprus properties at once
  • Then individually un-tick any that shouldn't be included
  • Manually tick individual properties from other countries if the bill spans them
Step 4 — Calculate Pro-Rata Amounts

Once your selection is made, click the Calculate Pro-Rata Amounts button (sits next to the property panel). This opens the Pro-Rata Expense Preview modal showing exactly what will happen if you save.

Step 5 — Review the Preview modal

The Preview displays:

  • Total Pro-Rata Amount at the top (e.g. €3,000)
  • Selected Properties count (e.g. 10)
  • A per-property table with four columns: Property — Current Value — Share % — Amount
  • Cancel — closes the modal without making any changes; you stay on the form so you can adjust selections
  • Confirm & Update — commits the distribution

The percentages always sum to 100%. The amounts always sum to the Total. Use this preview to sanity-check that the split feels right before committing.

Step 6 — Confirm & Update

Clicking Confirm & Update commits the changes:

  • For properties without an existing Expense for this Line Type → a new record is created
  • For properties with an existing Expense for this Line Type → the existing record is updated with the new amount
  • For properties that were previously included but are now un-ticked (Edit mode only) → their Expense records are removed as part of the recalculation

You're then redirected back to the Expenses listing page with a success message.

What's different in Edit mode

When you click Edit on an existing pro-rata Expense record:

  • The form opens with all previously-included properties pre-ticked — not just the anchor. So if a bill currently spans 10 properties, all 10 checkboxes are already checked when Edit opens. You only touch the ones you want to change.
  • The anchor property (the one you opened Edit on) is locked-in as before
  • You can add new properties to the distribution by ticking them, or remove existing ones by un-ticking them
  • You can change the Property, Expense Type, or Line Type dropdowns at the top — but bear in mind that changing the Line Type can take you out of pro-rata mode entirely
  • On Confirm & Update, the system deletes all original pro-rata records for this Line Type+Type combination and recreates them based on the new selection. This is how it cleanly handles additions, removals, and amount changes in one operation.
This is how the cascade works. One Calculate & Confirm cycle on any one Expense record refreshes the entire Line Type's distribution across all linked properties. You don't need to visit each property individually.
Practical Tips
Setup & entry
  • Set up Configuration first. Expense Types and Expense Line Types must exist before you can create an Expense record. If you're starting from scratch, build out the 12 single-month Types (January, February, …), the recurring Types (Monthly, Quarterly), and your Line Types before coming here.
  • One record per (Line Type + Type) combo per property. If a property has Property Manager fees of €52/month and €245 of Communal Fees in January, those are two separate records — one for each combination of Line Type and Type. Don't try to merge them.
  • Enter the per-month amount, not the annual. €52 monthly Property Manager fees go in as 52. €245 annual Communal Fees in January go in as 245. The Type handles the multiplication based on which months are flagged.
  • Match the Type carefully. The wrong Type produces a P&L that doesn't match reality. If utilities are billed Mar/Jun/Sep/Dec, use a Type with exactly those four months flagged — not Quarterly (which is Jan/Apr/Jul/Oct).
Working with Pro-Rata
  • The Line Type decides the flow. Pro-Rata isn't a checkbox on the Expense record — it's a property of the Line Type. Pick a Pro-Rata Line Type and the property panel appears automatically.
  • Always review the Preview before clicking Confirm & Update. The Preview modal is your last chance to catch a wrong selection before the cascade runs. Check the property list, check the share percentages, check the totals.
  • Use the Country filter as a starting point, not an end point. Click Cyprus to tick all Cyprus properties at once, then un-tick any that shouldn't be included (e.g. a Cyprus property that's in renovation and not yet generating expenses).
  • To update an existing pro-rata distribution, edit any one of the linked records. Open Eleftheroupoleos's Financials (Cyprus) record — any change you make and confirm cascades to all 10 (or however many) properties using that Line Type. You don't need to edit each property's record individually.
  • Pro-Rata Amount changes are handled on the Line Type page — with a live preview. If the total bill has shifted (e.g. €3,000 → €3,500), edit the Pro-Rata Amount on the Line Type and click Save. A preview modal opens showing every linked Expense record's old/new/Δ per property. Confirming with Save & Recalculate All saves the Line Type and cascades the new distribution to every linked record in one atomic operation. No separate Calculate-Confirm trip is needed anymore.
  • Current Value changes on the Property Valuations page also cascade automatically. When you edit a property's Current Value on the Valuations report, the system checks if that property is in any Pro-Rata distributions. If so, a preview modal opens showing every affected distribution (collapsible, one per Line Type) with the per-property ripple effect. Confirming commits the valuation change and recalculates every Pro-Rata Expense touching that property in one operation.
  • When a new property joins the portfolio, add it to existing pro-rata distributions. The new property won't auto-appear in existing pro-rata records. Open any one of the existing pro-rata Expense records, tick the new property in the panel, and re-calculate.
General awareness
  • Expense records aren't dated. They describe an ongoing pattern, not a transaction on a specific date. Changing the amount today rewrites the P&L for past months too.
  • Check the count badge as a sanity flag. If a property normally has 8 records and now shows 7, something's been deleted. Open it and verify nothing important is missing.
  • Properties with no records don't appear in the listing. A missing property = €0 contribution to the Expenses side of the P&L. Usually a bug to fix, not a feature.
  • If a P&L expense figure looks wrong, start here. Every budgeted expense on the P&L is calculated from the records on this page. Expand the relevant property and check.
Note: This page captures budgeted/recurring expenses that build the P&L Budget side — predictable costs you know about in advance. For actual one-off expenses with invoices and approval workflow (one-time repairs, ad-hoc maintenance, unexpected bills), use the Expenses module in the main sidebar instead.

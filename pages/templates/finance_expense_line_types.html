    What are Expense Line Types?

    An Expense Line Type defines the category of an expense — the label that will appear as a row in the Expenses section of the Profit & Loss Statement.

    Where Expense Types describe when an expense is paid (the months pattern), Expense Line Types describe what the expense actually is. They're the answer to: "What category of expense is this?"

    Examples already in your system

    Your Line Types fall into a few clear groupings:

    • Standard recurring expenses — Property Manager, Cleaning Costs, Garden Maint., Electricity, Refuse, Sewerage
    • Country-specific tax/professional fees — Financials (Cyprus), Financials (Greece), Financials (Spain), Insurance (Cyprus), Prop Tax (Cyprus)
    • Multi-instance recurring — Communal Fees 1, Communal Fees 2 (one Line Type per payment instance — see Tips for why)
    • Pro-Rata expenses — covered in their own tab
    Where this fits
    1. Expense Types — when the expense is paid
    2. Expense Line Types (this page) — what the expense is called on the P&L
    3. Expenses — the actual records: a property + a Line Type + a Type + an amount
    What's different from Revenue Line Types

    Two important differences worth noting up front:

    • You can delete an Expense Line Type (Revenue Line Types are Edit-only). The Delete button does a smart cascade check — see The Table tab.
    • An Expense Line Type can be marked Pro-Rata — meaning a single bill covering multiple properties is automatically split across them. See the Pro-Rata Explained tab for the full picture.
    Permissions: This page is restricted to Superusers.
    Reading the Table

    Each row is one Expense Line Type, with three columns:

    • Expense Line Type — the short name. This is what appears as the row label in the P&L.
    • Expense Line Type Description — a longer, human-readable explanation. Currently for your reference only; the P&L uses the short name.
    • Actions — an Edit button (light/grey) and a Delete button (red).
    The Edit button

    Opens the same form as Add New, with the four fields pre-filled (Name, Description, Pro-Rata Yes/No, Pro-Rata Amount). Make changes and click Save.

    The Delete button — the cascade check

    Clicking Delete doesn't immediately remove anything. Instead it opens a Confirm Delete modal that first scans the database for any Expense records using this Line Type:

    • If nothing is using it → you see a simple "Are you sure?" prompt. Click Delete to confirm.
    • If Expense records exist → you see the full list of every record that will also be deleted, with each entry showing: Expense ID, the property it belongs to, the Type assigned, the base amount, the total monthly amount, and a month-by-month breakdown.
    Cascade delete is permanent. Confirming the delete removes the Line Type and every linked Expense record across all properties. The deleted records cannot be recovered — you'd have to re-create each one manually. Read the linked-expenses list carefully before clicking Delete the second time.
    The detail view is your safety net. If you see records you weren't expecting (e.g. a Pro-Rata Line Type with 10 linked expenses you'd forgotten about), the modal lets you abort before any damage is done. Always glance through the list first.
    Adding an Expense Line Type

    Click Add New in the top-right. The form has four fields:

    1. Expense Line Type Name — the short label that will appear in the P&L (e.g. Property Manager, Insurance (Cyprus)).
    2. Expense Line Type Description — the longer explanation for your records (e.g. "Monthly property management fee").
    3. Pro-Rata (Yes/No) — defaults to "Select an option". Choose Yes only if this Line Type represents a single bill that should be split across multiple properties.
    4. Pro-Rata Amount — only used when Pro-Rata is set to Yes. Enter the total annual amount of the bill (e.g. 2810 for an annual €2,810 audit fee). Leave at 0 if Pro-Rata = No.

    Click Save. The new Line Type appears in the list and is immediately available to assign to Expense records.

    When should I set Pro-Rata = Yes?

    Set Pro-Rata to Yes when:

    • You receive one invoice that covers multiple properties (e.g. an audit firm bills you €2,810 for the whole Cyprus portfolio).
    • You want the cost split fairly across those properties (proportional to each property's Current Value), not arbitrarily.
    • Each property should end up with its own Expense record showing its share, but you only want to enter the bill once.

    Set Pro-Rata to No when each property's expense is captured individually — for example, each property has its own electricity bill at its own amount.

    Editing an existing Line Type

    Click the Edit button on the relevant row. The form is identical, with all four fields pre-filled. Update what you need and click Save.

    Renaming changes the P&L label immediately — including for all historical periods. The numbers don't change, only the label. Older P&L screenshots will no longer match the live page.
    Don't repurpose a Line Type. If you want a different category, create a new Line Type. Don't rename Electricity to Water — every existing Expense record tagged as Electricity will instantly be reclassified as Water in the P&L.
    Changing the Pro-Rata Amount triggers a live preview and cascade. When you change the Pro-Rata Amount on a Line Type that has linked Expense records (e.g. €2,810 → €3,000) and click Save, the system intercepts with a preview modal showing exactly what will happen:
    • Every linked Expense record is listed with its Old Amount / New Amount / Δ
    • Red Δ values indicate properties that will pay more; green Δ values indicate properties that will pay less
    • Clicking Save & Recalculate All saves the Line Type and updates every linked Expense record in one atomic operation
    • Clicking Cancel aborts — nothing is saved

    No more manual trips to the Expenses page — the cascade happens in a single click.

    What is a Pro-Rata Expense?

    A Pro-Rata Expense is a single bill that legitimately covers multiple properties, and that should be fairly split across them rather than dumped on one.

    Classic examples:

    • Audit fees — the auditor charges €2,810 to audit your whole Cyprus portfolio. That's not "Eleftheroupoleos's expense" — it should be shared across all the audited properties.
    • Annual company fees — a single fee that supports the whole legal entity owning multiple properties.
    • Country-wide insurance — a master policy covering all properties in one country.
    • Professional services — legal, tax preparation, consulting that benefits the portfolio rather than any one property.
    How Pro-Rata works in two stages
    Stage 1 — Setup (here, on the Line Type)
    • Set Pro-Rata = Yes
    • Enter the total annual bill in Pro-Rata Amount (e.g. €2,810)
    • Save
    Stage 2 — Capture (on the Expenses page)
    • Create an Expense record for any one of the affected properties
    • Pick the Pro-Rata Line Type — the Expense Amount is auto-filled with the total (€2,810) and locked
    • A property selection panel appears, with the current property auto-checked and locked-in
    • Tick the other properties this bill covers (or use the Country quick-filter to tick them all in one click)
    • Click Calculate Pro-Rata Amounts — a Pro-Rata Expense Preview modal opens showing the proposed split: each selected property with its Current Value, percentage Share, and calculated Amount
    • Review the preview — if the split looks right, click Confirm & Update; if not, click Cancel and adjust your property selection
    • On confirmation, the system creates new Expense records on the other properties (or updates existing ones) with each property's calculated share
    A worked example

    Audit fee: €2,810 total. Three Cyprus properties selected, with their Current Values:

    • Property A — Current Value €200,000
    • Property B — Current Value €800,000
    • Property C — Current Value €320,000

    Total combined value = €1,320,000. The split:

    • Property A: 200,000 ÷ 1,320,000 × €2,810 = €426
    • Property B: 800,000 ÷ 1,320,000 × €2,810 = €1,703
    • Property C: 320,000 ÷ 1,320,000 × €2,810 = €681

    The system creates/updates three Expense records, one per property, with these amounts. The P&L for Financials (Cyprus) then shows the correct share against each property.

    Things to know about the distribution
    • Current Value drives the split — higher-valued properties bear a bigger share, lower-valued properties less. Each property's Current Value is set on the Property record (under Properties → Edit) and is shown next to each checkbox in the property selection panel.
    • The current property is always included — you can't un-tick the property you're capturing the expense for, since you're creating its record.
    • The Country filter is a tickbox shortcut — selecting "Cyprus" auto-ticks all Cyprus properties. You can still un-tick individual ones afterwards if a property shouldn't be included.
    • Existing Expense records are updated, not duplicated — if Property B already had a Financials (Cyprus) Expense from a previous round, its amount is overwritten by the new calculation, not added on top.
    Things to be careful with
    • Changing the Pro-Rata Amount on the Line Type cascades automatically — with a preview. If you bump €2,810 to €3,000 on the Line Type page, clicking Save opens a preview modal showing the full before/after per-property breakdown. Confirming with Save & Recalculate All commits both the new Line Type amount and the redistributed Expense records in one atomic operation — no separate trip to the Expenses page needed.
    • Adding a new property to the portfolio doesn't auto-include it. Existing Pro-Rata Expense records won't pick up the new property. Open the Expense record on any one of the existing properties, tick the new one in the panel, and re-calculate.
    • Deleting a Pro-Rata Line Type cascades hard. Every Expense record on every property using this Line Type is deleted. The Confirm Delete modal lists all of them — read carefully.
    Practical Tips
    Naming & structure
    • Keep Names short. The Name appears in P&L tables where space is tight — one or two words is ideal. Use the Description for the longer wording.
    • Suffix country into the Name when needed. If you have audit fees in multiple jurisdictions, name them Financials (Cyprus), Financials (Greece), Financials (Spain) — not just Financials three times. Each becomes its own row in the P&L, which is exactly what you want for country-by-country tax reporting.
    • Be consistent. If one property's electricity is tagged Electricity and another's is tagged Power, they'll appear as two different rows in the P&L. Pick one name and stick with it.
    • Don't over-categorise. Too many Line Types fragments the P&L into a long list of tiny rows. Combine related minor expenses (e.g. don't split Bin Bags from Cleaning Products — both are Cleaning Costs).
    The "Communal Fees 1, 2, 3..." pattern

    You'll notice some Line Types are numbered (Communal Fees 1, Communal Fees 2). This is a deliberate workaround for a real limitation:

    The problem: A single Expense record stores one amount. So you can't say "€340 in January and €270 in July" with a single record — the two payments have different amounts.

    The solution: Split the conceptual Communal Fees into numbered Line Types — one per payment instance. Pair each with a single-month Expense Type:

    • Communal Fees 1 + January Expense Type + €340
    • Communal Fees 2 + July Expense Type + €270

    Properties with different schedules (annual, semi-annual, quarterly) coexist nicely because each one only uses the subset of numbered Line Types it needs.

    Working with Pro-Rata
    • Only mark Line Types as Pro-Rata when there's truly one bill. If each property has its own Insurance bill (different amounts, paid separately), don't use Pro-Rata — just create individual Expense records. Pro-Rata is for the "one invoice, many properties" scenario.
    • Re-run Calculate when adding/removing properties. The distribution doesn't auto-update when the property pool changes. After acquiring or selling a property, open any one of the Pro-Rata Expense records, adjust the property panel, and re-calculate.
    • Pro-Rata Amount changes cascade automatically. When you change the Pro-Rata Amount on a Line Type with linked Expense records, the system shows a preview modal with the full per-property impact (old/new/Δ). Confirming with Save & Recalculate All saves the Line Type and pushes the new distribution through every linked Expense record in one operation.
    Working with Delete
    • Always read the cascade list. The Confirm Delete modal shows every linked Expense that will be destroyed. For Pro-Rata Line Types this can be 10+ records across multiple properties — well worth a slow review.
    • Don't delete to "fix a typo". Use Edit to rename. Delete is for retiring a Line Type entirely — e.g. an expense category you no longer have at all.
    Note: This page configures Budgeted expense categories — the recurring/expected expenses that build the P&L Budget side. For actual one-off expenses with invoices and approval workflow (one-time repairs, ad-hoc maintenance, etc.), use the Expenses module in the main sidebar instead.

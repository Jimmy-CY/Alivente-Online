What is a Revenue record?

A Revenue record is a single income stream for a single property. It's where everything from Configuration finally comes together to describe a real-world income source — for example, "Apolloneon-Demetri earns €800 in monthly rent".

Each Revenue record is built from four pieces:

  1. Property — which property generates this income
  2. Revenue Line Type — what the income is (e.g. Rental, Levies)  →  becomes the row label in the P&L
  3. Revenue Type — when it's collected (e.g. Monthly, Summer)  →  controls which months the amount is counted
  4. Revenue Amount — how much (in euros) is collected per active month
A worked example

Looking at the table now — Apolloneon-Demetri has two Revenue records:

  • Rental / Monthly / €800  →  €800 of rental income every month, all year.
  • Levies / Monthly / €30  →  €30 of levy income every month, all year.

Together these give the property an annual income of (€800 × 12) + (€30 × 12) = €9,960, made up of €9,600 Rental + €360 Levies.

Where this fits

This is the final piece of the three-part Revenue configuration:

  1. Revenue Types — when income is collected (the months pattern)
  2. Revenue Line Types — what the income is called on the P&L
  3. Revenues (this page) — the actual records on each property

If you haven't set up Types and Line Types yet, do those first — the dropdowns on the Add Revenue form are populated from them.

Reading the Table

Records are grouped by property and presented as a list of collapsible rows — one row per property, with the records hidden inside until you expand the row.

Property header rows

Each property appears as a single bold row with three things:

  •  A chevron arrow on the left — right-pointing when collapsed, down-pointing when expanded.
  • The property name.
  • A teal 2 count badge showing how many Revenue records that property has.
Expanding and collapsing
  • Click a property header to expand it. The chevron rotates down and the records appear below.
  • Click the same header again to collapse it.
  • Click a different property's header and the previously-open one auto-collapses — only one property can be open at a time. This keeps the page tidy when you have many properties.
Inside each property

One row per Revenue record, with five columns:

  • Property — the property name (repeated for clarity).
  • Revenue Line Type — the category (e.g. Rental, Levies).
  • Revenue Type — the months pattern (e.g. Monthly, Summer).
  • Revenue Amount — the euro amount per active month, formatted with thousand separators (e.g. € 800, € 1,250).
  • Details — an Edit button to modify that record.
Properties without revenue records don't appear here. If a property is missing from the list, it has no Revenue records yet — click Add New to create one for it.
Adding a Revenue record

Click Add New in the top-right to open the Add Revenue form. You'll see four fields in a row:

  1. Property — dropdown of all your active properties. Pick the one this income belongs to.
  2. Revenue Line Type — dropdown populated from the Revenue Line Types page (e.g. Rental, Levies).
  3. Revenue Type — dropdown populated from the Revenue Types page (e.g. Monthly, Summer).
  4. Revenue Amount — the euro amount collected per active month (a numeric value, no currency symbol needed).

Click Save in the top-right and the new record appears in the property's group on the listing page.

The amount is per active month, not per year. If a property earns €800 in monthly rent, enter 800 — not 9,600. The system multiplies by the months your chosen Type marks as active. So €800 paired with Monthly = €9,600/year, but €800 paired with Summer (May–Oct) = €4,800/year.
One record per income stream

If a property has multiple income streams — rent, levies, parking, storage — create a separate Revenue record for each. This keeps the P&L breakdown by Line Type meaningful and makes it easy to track each income stream independently.

Editing an existing Revenue record

Expand the property's row, then click the Edit button on the relevant record. The form is identical to the Add form, with all four fields pre-filled. Update what you need and click Save.

Edits affect the P&L immediately — including history. Revenue records aren't dated — they describe an ongoing pattern. Changing the amount from €800 to €900 instantly recalculates the P&L for every month, every year, including past periods. If you need to capture a rent increase mid-year while preserving history, the cleanest approach is to delete-and-recreate, or simply note the change date externally.
How Revenue records build the Profit & Loss Statement

The P&L doesn't store revenue numbers — it calculates them every time you open it, by walking through your Revenue records and applying a simple three-step formula.

The formula
  1. For each Revenue record → look up its Revenue Type to see which months are active.
  2. For each active month → the record contributes its amount to that month.
  3. For each month → group all contributions by Revenue Line Type → that's the row in the P&L Revenue section.
A worked example with two properties

Suppose you have:

  • Property A: Rental / Monthly / €800   +   Levies / Monthly / €30
  • Property B: Rental / Summer / €1,000

Step through the months:

  • January — Property A pays €800 rental + €30 levies. Property B pays €0 (Summer doesn't include January).
  • June — Property A pays €800 + €30. Property B pays €1,000.
  • December — Property A pays €800 + €30. Property B pays €0.

Now group by Line Type for each month and you get:

  • Rental row: €800 (Jan), €800 (Feb), …, €1,800 (May–Oct), …, €800 (Dec)  →  total €15,600/year
  • Levies row: €30 every month  →  total €360/year
The P&L is fully derived. Every revenue figure on the P&L can be traced back to a specific Revenue record on this page. If a number on the P&L looks wrong, the answer is always somewhere here — either an incorrect amount, the wrong Type assigned, or a missing record.
Drilling down from the P&L

On the P&L Statement, every blue revenue number is clickable. Clicking it opens a breakdown showing exactly which properties contributed to that figure — making it easy to trace any value back to the underlying records.

Practical Tips
  • Set up Configuration first. Revenue Types and Revenue Line Types must exist before you can create a Revenue record — the dropdowns won't have anything to pick. If you're starting from scratch, create at least Monthly (Type) and Rental (Line Type) before coming here.
  • One record per income stream per property. If a property earns rent and levies, create two records, not one combined one. The P&L groups by Line Type, so combined records lose the breakdown.
  • Enter the per-month amount, not the annual. The most common new-user mistake is entering €9,600 (the yearly figure) for a €800/month rental. The Type handles the multiplication — just enter 800.
  • Match the Type to reality. If a property is rented year-round, use Monthly. If it's a holiday let active May–Oct, use Summer. The wrong Type produces a P&L that doesn't match what's actually happening.
  • Use the Edit button for changes, not delete-then-recreate. Editing preserves the record's identity and is the right tool for amount adjustments, Type changes, or fixing typos. Delete-and-recreate is only needed if you want to break P&L history for that record.
  • Be aware that edits change history. Revenue records describe an ongoing pattern, not a dated transaction. Changing the amount today instantly rewrites the P&L for past months too. If you need a true dated change (e.g. rent increased on 1 July), keep external notes — the system shows the current state only.
  • Check the count badge. The teal number next to each property name tells you how many Revenue records it has. A property showing 1 when you'd expect 2 (rent + levies) is a quick visual flag that something's missing.
  • Properties with no records don't show. If a property is missing from the list entirely, it has zero Revenue records — meaning it currently contributes €0 to the P&L. This is usually a bug to fix, not a feature.
  • If a P&L number looks wrong, start here. Every revenue figure on the P&L is calculated from the records on this page. There are no other inputs — so if something looks off, expand the relevant property and check the records.
Next step: With Revenues set up, your P&L will show the income side of the picture. To complete it, head to the Expense side — Expense Types, Expense Line Types, and Expenses — which work the same way.

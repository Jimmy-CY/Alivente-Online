What is the Properties Module?

The Properties module is the central hub of Alivente Online. It lets you manage your entire property portfolio — from recording property details and locations to tracking assets, title deeds, utility accounts, and generating property reports.

Every other module in the system depends on the data you capture here. Tenants attach to properties; revenues, expenses, and valuations all reference properties; reports like the P&L and Vacancy Management aggregate data across properties. Getting this module right pays dividends everywhere else.

Key features
Property List

Every property at a glance with its country, status, and quick-access action buttons for editing, viewing the report, opening the title deed, and browsing assets.

Map View

See all properties plotted on an interactive map. Instantly visualise your portfolio's geographic spread. Click Map View in the top action bar.

Property Reports

Generate a detailed report for any property — address, specifications, utility accounts, insurance, status, and a full asset summary. Useful for meetings with lawyers, accountants, or tenants.

Title Deeds

Upload and store PDF title deeds for each property. View and download them at any time directly from the property list — a secure, centralised home for your legal documents.

Asset Tracking

Record every physical asset (appliances, electronics, furniture) within each property, including brand, purchase date, supplier, and warranty expiry.

Filtering

Filter properties by name, country, and status. Active filters are shown as removable tags. Use Clear All to reset.

Photo Documentation

Attach up to 5 photos per asset (JPG/PNG, 5MB each). On mobile, use the Take Photo button to capture photos on the spot. Cover thumbnails appear in the asset list and detail header.

Category or Room Grouping

Switch the Asset Manager between category-grouped and room-grouped views with a single click — useful for walkthroughs vs maintenance planning.

Important: Properties marked as Active and Available for Rent are included in vacancy calculations across the system. Make sure your property statuses are kept up to date — stale statuses lead to misleading dashboards.
Understanding the Property List

Each row on the table represents one property. The columns are:

The 7 columns
  • Property — The property name as entered in the system.
  • Country — The country where the property is located (Cyprus, Greece, Spain, etc.).
  • Status — Either Active (included in all calculations) or Inactive (excluded from vacancy and occupancy calculations).
  • Details — Opens the Edit Property form (superuser-only for editing; others see a disabled button).
  • Report — Generates the full Property Details Report (address, specifications, utility accounts, asset summary).
  • Title Deed — Opens the stored title deed PDF in a viewer. Shows "Unavailable" if none has been uploaded.
  • Assets — Opens the Asset Manager for this property. Shows "None" if no assets have been recorded.
Using the filter panel

Click the Property Filters bar at the top to expand filter options. You can filter by:

  • Search Property — free-text search on the property name
  • Country — dropdown with each country represented in your portfolio
  • Status — Active or Inactive

Filters are combinative — all selected filters apply at the same time. Active filter tags appear at the bottom of the panel and can be removed individually, or use Clear All to reset everything.

Map View

Click the Map View button at the top to see all properties as pins on an interactive map. The pins respect the current filter — so if you're filtered to Cyprus only, only Cyprus properties appear on the map. Use Center Map to reset the zoom to show all visible properties.

Tip: For a property to show on the Map View, its address must be correctly geocoded. If a property is missing from the map, open its Edit form and check the map location — you may need to use Find Address on Map to set or correct the pin.
Adding and Editing Properties

Click Add New in the top-right to create a new property, or the Edit button on any row to update an existing one. Both forms contain the same six sections.

1. Property Name

Give it a clear, descriptive name (e.g. "Ionion - Villa 24"). This name appears throughout the system — on the P&L rows, in tenant records, in reports, on maps. A consistent naming convention helps enormously: prefix by building or area, then unit identifier.

2. Address

Fill in the full address — Address Line 1, Address Line 2, Suburb, City, Province, Country, Post Code. A complete address ensures accurate map placement and correctly-rendered reports.

3. Map Location

Two ways to set the pin:

  • Click directly on the map — drops a pin at the clicked location
  • Use "Find Address on Map" — auto-locates the pin based on the address fields you've filled in

Use Clear Location to remove a saved pin. A pin is required for Map View to display the property.

4. Specifications
  • Floor Area (m²) — used for the Rent/m² KPI on Financial Indicators
  • Year Built — informational
  • Include in Occupancy Calculations — Yes means this property counts on Vacancy Management and Performance Trends. Set to No for owner-occupied properties, short-term/summer-let properties, or properties not rented on a traditional basis.
5. Status & Availability
  • Status — Active or Inactive. Inactive properties are hidden from most reports.
  • Available for Rent — Active + Available for Rent + no current tenant = counts as Vacant in Notifications and the Dashboard.
  • Title Deed Available — indicates whether you hold a deed for this property. The actual PDF is uploaded separately.
6. Utility Accounts

Record account numbers and supplier info for:

  • Electricity
  • Water
  • Refuse
  • Property Tax
  • Sewerage
  • Insurance

These appear on the Property Report as a central reference for all service accounts, so you don't have to search through paperwork when a bill arrives or a service needs to be contacted.

Adding vs Editing: The form is identical in both cases — the only difference is that Add New starts blank, while Edit pre-fills every field with the current values. Only Superusers can add properties; Superusers and ordinary users can edit (check the row-level button to see your permission).
Managing Property Assets

Each property can have unlimited assets — appliances, electronics, furniture, and more. Assets are grouped by category in the Asset Manager, and are summarised in the Property Report.

Accessing the Asset Manager

Two ways to open a property's assets:

  • From the Property List — click View in the Assets column (only appears if at least one asset exists)
  • From the Edit form — open the property's Edit form, then click the Assets button in the top-right. This works even if no assets exist yet — it's how you add the first one.
Information recorded per asset
  • Asset Name — e.g. "Samsung Washing Machine"
  • Brand — the manufacturer
  • Category — Appliances, Electronics, Furniture, etc.
  • Subcategory — e.g. Air Conditioner, TV, Sofa
  • Location / Room — e.g. Lounge, Kitchen, Master Bedroom
  • Purchase Date — when the asset was acquired
  • Supplier — where it was bought
  • Warranty Expiry Date — when the warranty ends
Warranty status

Each asset shows one of three warranty badges:

Active — warranty expiry is in the future; the asset is still under warranty.
Expired — warranty expiry is in the past; repairs are now at your cost.
N/A — no warranty expiry date recorded (incomplete data).
Property Report integration: The Property Details Report includes an Asset Summary section showing total asset count, active vs expired warranties, total purchase value, and maintenance cost indicators. Keep assets up to date and the report becomes a powerful portfolio inventory.
Asset Photos & Viewing Options

The Asset Manager supports up to five photos per asset and two different ways of grouping the list. Both features make managing large portfolios with lots of assets much faster.

Category vs Room grouping

By default, assets are grouped by their Category (Appliances, Electronics, Furniture, etc.). Use the toggle buttons at the top of the assets page to switch to Location / Room grouping — useful when you're walking through a property room by room (inventory check, planning a clean, showing a tenant around).

  • Category view — section headers show a tag icon. Best for purchase / maintenance planning.
  • Location / Room view — section headers show a door icon. Best for room-by-room walkthroughs.

The toggle is bookmarkable and refresh-safe — your choice is preserved in the page URL.

Adding photos

When adding a new asset, the Add Asset form includes a Photos field. When editing an existing asset, a dedicated Photos section appears between Purchase Invoice and Notes.

Limits per asset:

  • Up to 5 photos
  • Maximum 5 MB per photo
  • Format: JPG or PNG only

The form enforces these limits before upload — if you pick too many photos or one that's too large, you'll see an inline error before the form submits.

Mobile camera capture: When using a phone or tablet, a green Take Photo button appears next to the file picker. Tap it to open the device camera directly and snap a photo of the asset on the spot — no need to take photos first and upload them later. Use the regular file picker for selecting existing photos from your camera roll.
The cover photo

The first photo in the list is the asset's cover photo — it's the thumbnail shown on the asset list and at the top of the asset detail page. To promote a different photo to cover, open the asset's Edit page and click the star icon on the photo you want as cover.

  • Gold filled star — this is the current cover photo.
  • Grey outline star — click to make this photo the cover.
Deleting photos

On the Edit page, each photo has a red trash icon in its corner. Clicking it shows a confirmation popup before the photo is permanently removed. The deletion is immediate — you don't need to click Save Changes afterwards.

Where photos appear
Asset list rows

Each row in the Asset Manager shows a 50×50 thumbnail of the cover photo before the asset name. Assets with no photos show a placeholder box icon — an at-a-glance reminder of which assets still need documentation.

Asset detail page header

A 60×60 thumbnail of the cover photo replaces the generic briefcase icon at the top of the detail page. Click the thumbnail to open the photo in a full-size lightbox.

Photos card on detail page

When an asset has photos, a dedicated Photos card appears between Asset Info and Warranty on the detail page. Each photo shows as a 160×160 tile (50% width on mobile). Click any tile to open it in a lightbox modal.

Use photos to settle disputes. At handover, photograph each major asset (appliances, electronics, furniture) and add the photo to its record. If a tenant later disputes the condition of an item, the dated record on the asset is the easiest reference to reach for.
Practical Tips
Setting properties up correctly
  • Always set the map location. After entering the address, use Find Address on Map — it auto-places the pin with good accuracy. Properties without a pin won't appear on Map View.
  • Keep statuses up to date. Active + Available for Rent properties with no tenant show as Vacant in Notifications. Stale statuses mislead the whole dashboard — update as soon as a property goes into or out of service.
  • Upload title deeds early. As soon as a deed becomes available, upload the PDF. It creates a secure, centralised home for your legal documents and makes them easy to share with lawyers, tax authorities, or potential buyers.
  • Choose consistent naming. Whatever convention you pick ("Building - Unit", "City-StreetName", etc.), use it for every property. Reports, dropdowns, and filters all work better with predictable names.
Capturing assets properly
  • Record warranty dates when you capture the asset. Once the receipt is filed away, warranty info is easy to forget. Enter it the moment the asset is installed.
  • Use meaningful Location/Room values. "Kitchen" and "Master Bedroom" are much more useful than generic labels when a maintenance engineer needs to know where to go.
  • Keep supplier info. When an item fails, knowing where it was bought (and whether it's still under warranty) saves hours of scrolling through emails.
  • Photograph at handover and on replacement. One or two photos per asset is enough to settle most condition disputes — take them the moment the asset is installed and again when it's replaced. Use the mobile Take Photo button to do this on the spot during a property visit.
  • Promote the best shot to cover. Use the gold star on the Edit page to set the most representative photo as the cover. That's the one tenants and contractors see on the list and the detail header.
Making the module work for you
  • Fill in utility account details. Account numbers for electricity, water, refuse, and other services centralised in one place saves time every time a bill needs to be queried.
  • Use the Property Report regularly. The one-page Property Details Report is the best summary document for meetings with lawyers, accountants, property managers, or tenants. Print or PDF-export before any such meeting.
  • Use Map View for portfolio reviews. Visualising your portfolio geographically can reveal patterns — a cluster of underperforming properties in one area, or over-concentration in a single city.
  • Remember the Include in Occupancy flag. This flag on each property controls whether it appears on Vacancy Management and Performance Trends. Owner-occupied or short-term rentals should be set to No; long-term rentals should be set to Yes.
Properties is the foundation. Every other module in Alivente Online — Tenants, Revenues, Expenses, the P&L, Vacancy Management — builds on the data you capture here. Time spent keeping property records accurate and complete is repaid across the entire system.

How the Notification System Works

Who gets an email about an event is decided by two independent choices, combined with the timing you set on the event. A person is emailed only when all three line up.

1
Who the event is about — “Relevant to” (set on the event)
Every event has a Relevant to list showing each active household member with a tick box. Tick the people the event pertains to. You can do this two ways:
  • Directly on the event card — the tick boxes save instantly.
  • In the event’s Add / Edit form, under “Relevant to”.
The list is drawn from your Household Members roster, so adding a person there makes them available on every event automatically.
2
Who wants celebration emails — opt-in (set on the roster)
Go to Personal → Household Members. Each person has a Celebration reminders tick box — tick it to opt them in, untick to opt them out. Their email address (also on that page) is where the reminder is sent.

A person with no email, or who is set to Inactive, is never emailed — even if they are marked relevant to an event.
3
When the reminder is sent — timing (set on the event)
When adding or editing an event, choose when reminders go out under Notification Settings:
Notify 1 week before (9:00 AM)
Notify 1 day before (9:00 AM)
Notify same day (9:00 AM)

New events default to same day only — tick the earlier reminders as well for events you want more notice on.
The rule — all three must line up
A person receives a celebration email if and only if:
✓ They are ticked under Relevant to on that event
✓ They are opted in to Celebration reminders on the roster (and have an email, and are active)
✓ Today matches the event’s timing (1 week / 1 day / same day)
Put simply: recipients = people the event is about ∩ people who opted in, sent on the days you chose.
Fully automatic: once relevance and opt-ins are set, reminders send themselves at 9:00 AM on the matching days. Nothing to do on the day.

Meal Plans

The calendar is the plan. Meals belong to dates, not to a named plan you have to make first: open the planner, click Add Recipe on a day, and that meal is planned. There is nothing to name, nothing to date, and nothing to save.

One screen. A month to pick a week from on the left, and the week you picked opened on the right, a card for each of its seven days. It opens on this week every time.
Then shop for it. Shopping List at the top takes the week you are looking at and turns it into one list — every ingredient across every meal, added up, converted into what you buy it in, and grouped by aisle.
Everyone sees the same calendar. Meals are not private to the person who planned them — this is deliberate, and it matches the recipes they are built from, which are shared across the whole installation. If you can open Recipes, you can see the planner.
No length, and nothing overlaps. There is one calendar, so two weeks cannot clash and no plan has to end. Plan a fortnight by planning fourteen days.
Past dates are allowed. Nothing stops you planning backwards, and that is useful: a week filled in after the fact is a record of what you actually ate, and the shopping list will still tell you what it cost in ingredients.
If you used Meal Plans before 18 October 2026: the named plans, the two screens that made them, the page that showed one and the button that copied it have all gone. Everything they did, the calendar does in one place — and the test plans that were there have been cleared.
The Calendar

One calendar, at three zoom levels. Month for the shape of a month, Week for seven days side by side, Day for one day in full. The same meals, the same dates, drawn three ways — and the view you are in decides what the buttons at the top act on.

Month, Week, Day is a switcher on the bar at the top, and it is the first thing to decide: everything else on that bar follows it. Today returns you to today at whatever zoom you are on.
A day is a day in every view. Click one in the month and it opens in Day; click one in the week and the same thing happens. You are never dropped somewhere you did not ask for, and a dialog returns you to the day you were on.
The dots in the month grid mark days that have at least one meal on them, so you can see at a glance which weeks are planned and which are empty. Today is marked as well, in its own colour.
The arrows move by whatever you are looking at. A month in Month, a week in Week, a day in Day — one pair of arrows, and they always step by the unit on screen. Every date is reachable and every date can take a meal; there is no range to stay inside.
Add on any day, in any view. Every day carries a way in — the + on a month cell, the one on a week column, Add Recipe on the day card — and all three open the same picker, titled with the date you pressed.
A meal is a chip, and the chip has a menu. Click one and four things are offered: View opens the recipe without leaving the calendar, Move puts it on another day, Leftovers puts a free second helping on a later one, and Remove takes it off — the one meal, not the day. A note has only Move and Remove, because there is no recipe behind it to view or to have leftovers of.
The colours mean something. A leftover is drawn quieter than the meal it came from and says so, and a note is drawn differently again. At a glance a week tells you which nights are cooking and which are not.
Tip: where you are travels with you. Go to the shopping list, print a plan, open a recipe, add a note — and you come back to the same view on the same day, not to this week.
Adding a meal to a day

Press Add Recipe on a day, choose a recipe, press Add Meal. That is the whole of it — there is no form to fill in and no Save button, because there is nothing to save but the meal itself.

The picker adds on a click, and stays open. It lists every recipe with its photo and the servings it makes, titled Add a meal to the date you came from, and it searches and filters exactly as the recipe library does. Click a recipe and it is on the day — no second button — and the strip underneath shows what is on that day so far, so a mis-click is something you can see and undo rather than discover later. Done closes it and the calendar comes back with everything you added.
Servings come from the recipe. A meal arrives making what the recipe's own yield says it makes. Nothing is assumed and nothing is set to four.
The stepper changes them, and saves as you press. The − and + beside a meal change how many it is for, and each press is stored straight away. One is the floor — a meal for nobody is not a meal. The shopping list scales every ingredient by whatever you set here.
As many meals a day as you like. Breakfast, lunch and dinner on the same card, in the order you added them. There is no slot to fill and none to leave empty.
Add Note, for a night you are not cooking. Eat out, takeaway, at a friend's. It sits on the day like a meal does, so the week reads as a plan rather than as a plan with holes in it — and it buys nothing: a note never reaches the shopping list. Three suggestions are offered so a planned night is one tap. Note is in the picker's own footer as well, so a night you are not cooking does not need the picker closed first.
Leftovers, and they are free. The button beside a meal puts it on another day as leftovers. It costs nothing on the shopping list — you bought the ingredients on the night you cooked — so a pot of soup that feeds you three times is bought once. The leftover row names the day it was cooked on and has no servings stepper, because changing that number would buy nothing.
Or from the recipe library, without opening the planner at all. Every recipe card carries a calendar beside its heart. Press it and three shortcuts are offered — Today, Tomorrow and this Saturday — with a small month underneath for any other date. The meal is added where you stand, and the message that confirms it carries an Undo.
And the photo is a quick look. Clicking a recipe's picture in the library opens it to read — ingredients, method, servings — without leaving the list you were browsing. It is the fastest way to decide whether a recipe is tonight's before you plan it.
It works on a phone. The picker, the stepper, the chip menu, the calendar button and the day cards are all built for a narrow screen, which is where a week usually gets planned.
Drag to reorder: the grip at the left of each meal reorders that day - the same handle the ingredient and instruction lists use - and in the week view the meals themselves drag up and down their own column. Not yet, and coming: dragging a meal from one day to another. That writes a date rather than an order, so for now it is Move on the chip menu.
Copying days, and saving them

Two buttons on the planner's own bar — Copy… and Saved Menus… — beside Shopping List and Print. On a phone they move into the menu, which is where a narrow screen puts every secondary.

Copy meals to another date. Any stretch of days, not just a week. This day, This week and This month fill the two dates in for you, or type them yourself — a long weekend, ten days, a fortnight. Every meal in that stretch lands on the matching day of the new dates, with the servings it was cooked for, and the originals stay exactly where they are. Nothing is linked afterwards: change the copy and the first one does not move.
Saved Menus. One dialog, three things. Save these days keeps a stretch of days under a name — From and To, with the same This day, This week and This month presets Copy has, up to 92 days. What is stored is how far into the menu each day falls and not a date, which is the difference between a Menu and a copy: a Christmas menu built on 23 December is kept as “day 1, day 3, day 10” and can be stamped onto any dates at all. Your menus lists what you have saved, each row saying how many meals it holds and over how many days, and carries a trashcan to forget it. What is the Household Members page?

Household Members is the single roster of the people in your household. It does two jobs:

  • It lists the people events can be about. Everyone here appears as a tick box on each celebration event’s “Relevant to” list.
  • It controls who receives which notifications. Each person opts in or out of each notification type using the tick-box columns.

It replaces the old Personal Notification Settings page, which used free-typed email lists. Now each person is a row, with their own email and their own opt-ins.

Shared across modules. The same roster feeds Celebrations (celebration reminders) and Passports / IDs (document-expiry alerts), so you manage your people in one place.
A person is emailed only if they have an email address, are Active, and are opted in to that notification type. Inactive or email-less people are simply skipped.
Reading the roster

Each row is one person. The columns are:

  • Name — how the person appears on events and in reminders.
  • Email — where their notifications are sent. Shows no email if blank (they then can’t be emailed).
  • Linked account — the login user this person maps to, if any. People don’t have to be logins — they can be audience-only.
  • Status — Active or Inactive. Inactive people are hidden from events and never emailed.
  • Opt-in columns — one tick box per notification type (e.g. Celebration reminders, Document expiry). Tick to opt the person in, untick to opt out. Changes save instantly.
  • Actions — Edit, Activate / Deactivate, and Delete (write access required).
The opt-in columns you can change depend on your access — you see and edit the columns for the modules you have permission to.
Two separate choices

It helps to keep two ideas apart:

Relevance — per event

Set on each celebration event (its “Relevant to” list): which people that particular event is about. A child’s birthday might be relevant to the whole family; a colleague’s to one person.

Opt-in — per person

Set here on the roster: whether a person wants a given kind of notification at all. Someone can opt out of celebration reminders entirely without being removed from any event.

The two combine: an event’s reminder goes to the people who are both marked relevant to that event and opted in here. Changing one never disturbs the other.
Adding and editing people

Click Add Person (or the pencil on a row) to open the form:

  • Name (required) — the display name used on events and reminders.
  • Linked login account (optional) — pick a system user to link this person to. Choosing one auto-fills the email below if it’s empty. Leave as None for someone who isn’t a login.
  • Email (required) — where this person’s notifications go.
  • Active — untick to retire a person without deleting them (keeps their history; removes them from events and emails).
Deactivate rather than delete when someone should simply stop receiving notifications. Delete is permanent and removes the person from the roster entirely.
Best practices
  • Add everyone once. Build the roster first — then every celebration event can reference the same people.
  • Set the email carefully. No email means no notifications, however the opt-ins are set.
  • Use opt-in as a “mute”. To stop someone’s celebration emails without editing every event, just untick their Celebration reminders column here.
  • Not receiving an expected reminder? Check three things: the person is ticked Relevant to on the event, opted in here, and the event’s timing matches today.
  • Deactivate people who leave rather than deleting — it keeps past context intact and is reversible.

What is Lease Signing?

Lease Signing sends a lease agreement out to be signed online. Each attempt is called an envelope: one lease, one tenancy, signed once. The order is always the same:

  1. You start e-signing — choose the tenancy and the lease PDF.
  2. Alivente signs first — a tenant never sees a lease Alivente has not already committed to.
  3. The tenants are emailed a link the moment Alivente signs — one link each, no login needed.
  4. Each tenant reads to the end and signs.
  5. The last signature seals the lease — a signature page is added and everybody who signed is emailed a copy, at the address their link went to, with Alivente copied. The addresses on the tenant record are not used for this.
  6. You approve it — only then does the signed PDF become the tenant’s lease agreement.
How to get here

Administration Functional Manage Lease Signing.

Superuser only: the register, the envelope pages, the signed leases and every action on them are for Superusers. Anybody else sees the tile greyed out. Signing itself is different: whoever is named to sign — a tenant, or a member of staff signing for Alivente — signs from their emailed link.
The original is never touched. Signatures go on a page added at the end, so the lease everybody signed is exactly the lease that was sent. The signed file’s fingerprint (SHA-256) is recorded, so any later change to it can be detected.
Starting an envelope

Press Start e-signing on the register.

  • Tenant — the tenancy the lease is for. If it already has an envelope open you are warned: starting another does not cancel the first.
  • The document — attach the lease to be signed as a PDF (PDF only, up to 15MB). The lease already on the tenant record is never offered: it is the one that tenancy has already signed. A lease made in Generate downloads as a Word file — check it, save it as a PDF, and attach that. The file belongs to the envelope, so anything done on Manage Lease Agreements later cannot change what was signed.
  • Signing for Alivente — leave it as yourself and you sign on the next screen. Name somebody else and they are emailed a link instead.
  • Tenants — filled in from the tenant record; at most two, with two different email addresses so the record can tell who signed. A second signer appears only when the tenancy has a second tenant.
  • Days to sign — 7 unless you change it (1 to 60). The link stays open until the end of the closing day, Cyprus time.

Press Create and sign. The envelope is a Draft until Alivente signs; nothing reaches a tenant before then.

The signing page

Everybody signs on the same page. It shows the property address (never the internal property name), the tenancy, the lease period and the closing date, then every page of the lease.

  • Read to the end — the signing box stays locked until the last page has been on screen.
  • Sign — Draw it with a finger or mouse, or Type my name. Drawn signatures print in blue.
  • Agree — tick that the electronic signature is as binding as one on paper, then Sign the agreement.
Signing for Alivente yourself

A third tab, Use my saved signature, is offered and already selected — but only to the account that saved it, signed in. Your saved signature and the company stamp are placed on the signature page, which simply says Signed. There is no Decline button for Alivente. Afterwards, Back to Lease Signing returns you to the register.

What the tenant receives

An email, “Please sign your lease agreement” with the address, carrying the small Alivente logo and no contact details. It says Alivente has already signed, gives their own link, and the date it stays open until. On the page they see who signed for Alivente and who else is signing, and a Decline to sign button.

You are told as each person signs. Alivente gets a short email each time somebody signs; the last one says the lease is ready for approval and links to the envelope.
Reading the register

One row per envelope, newest first. Live envelopes only, until you press Include finished.

  • Status — Draft · Out for signature · Partly signed · Signed · Expired · Cancelled · Declined.
  • Signers — how many have signed, then one dot per person, Alivente first: a tick has signed, a dot is still to sign, a cross declined. Hover over one to see the name and when they signed.
  • Expires — the closing date; “past its date” until the next check marks it Expired; awaiting approval once everybody has signed.

Row actions: view the envelope · view the signed lease (once there is one) · Extend · Cancel.

What happens while you wait
Reminders

On day 3 and on the day before the closing day (day 3 and day 6 of the usual seven), to whoever has not signed — never to somebody who has. They go out with the morning run, at about 08:00 Cyprus time. Each reminder carries a fresh link; the earlier one stops working.

Expiry

The link stops working at the end of the closing day, Cyprus time, and shows “the signing period has ended”. The register marks the envelope Expired the next morning (until then it says “past its date”). Every signature already given is kept.

Extend

Available before and after expiry. The new closing date is the end of the day seven days from today, and only the people still to sign get “More time to sign” with a fresh link. An expired envelope reopens as it was — nobody signs twice.

Cancel

Withdraws an envelope at any point before everybody has signed. Its links show “This agreement was withdrawn”. Signatures already given are kept on the record.

When a tenant declines

A tenant who presses Decline to sign ends the envelope for everybody: its status becomes Declined, the other tenant’s link stops working, and Alivente is emailed who declined and when. There is no reason field.

If the lease needs changing, start a new envelope. Attempt one and attempt two stay separate on the register, which is a cleaner record than one envelope that changed its mind.
Approving a signed lease

A fully signed lease is not written onto the tenant by itself. It waits for you, and you are told in three places: the Home page, Notifications, and a note at the top of the register.

Open the envelope (the awaiting approval link or the icon). It shows the signed lease, who signed, when and from where, the full trail, and what is attached to the tenancy now.

  • Approve and attach — choose the tenancy under Attach to and the signed PDF becomes its lease agreement on Manage Lease Agreements. Only tenancies at that property with no lease attached are offered: a lease is never replaced. The envelope’s own tenancy is chosen first when it is free.
  • Decline — nothing is attached. This is final: to attach that lease later, start a new envelope.
A renewal is a new tenancy. Add it first (Add Tenant, with the new dates), then Start e-signing and pick it — each tenancy is listed with its dates, and one that already has a lease says so. The old tenancy keeps its signed lease. If every tenancy at the property already has a lease, Approve is greyed out until you delete one on Manage Lease Agreements.
Viewing, downloading and sharing

View signed lease on the envelope page, or the icon on its register row, opens the signed PDF. Download is always there; on a phone, Share opens the phone’s own share menu (WhatsApp, Mail and so on) with the PDF attached.

Deleting an envelope

From the bottom of the envelope page, and only for a closed envelope — Cancelled, Expired, Declined or Signed. A live one must be cancelled first.

The page warns you how many signatures it holds; type the envelope number to confirm. Everything is removed — the envelope, its signers, its trail and its files. A lease already approved onto the tenant is a separate copy and stays on the tenant record.

Signature and Stamp

Administration System Signature and Stamp. Upload your signature and the company stamp as a PNG or JPEG (a scan on white paper is fine — the paper is made transparent).

They are kept in the database, never as a file or a link, and they are used only when the account that saved them signs for Alivente while signed in. Nobody else signing for Alivente gets them, whatever name is typed. Leases already signed keep the copy they were signed with.

Best practices
  • Check the tenant record first — the signers come from it, so a wrong email there is a link sent to the wrong person.
  • Sign straight away — nothing reaches the tenant until Alivente has signed, and the closing date is counted from the day you start.
  • Use Extend rather than starting again when somebody is simply slow — signatures already given are kept.
  • Start a new envelope when the lease changes — after a decline, or a correction to the document.
  • Approve promptly — until you do, the tenant record still holds the old lease.

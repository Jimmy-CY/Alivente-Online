What is the Properties Module?

The Properties module is the central hub of Alivente Online. It lets you manage your entire property portfolio — from recording property details and locations to tracking assets, title deeds, utility accounts, and generating property reports.

Every other module in the system depends on the data you capture here. Tenants attach to properties; revenues, expenses, and valuations all reference properties; reports like the P&L and Vacancy Management aggregate data across properties. Getting this module right pays dividends everywhere else.

Key features
Property List

Every property at a glance with its country, status, and quick-access action buttons for editing, viewing the report, opening the title deed, and browsing assets.

Map View

See all properties plotted on an interactive map. Instantly visualise your portfolio's geographic spread. Click Map View in the top action bar.

Property Reports

Generate a detailed report for any property — address, specifications, utility accounts, insurance, status, and a full asset summary. Useful for meetings with lawyers, accountants, or tenants.

Title Deeds

Upload and store PDF title deeds for each property. View and download them at any time directly from the property list — a secure, centralised home for your legal documents.

Asset Tracking

Record every physical asset (appliances, electronics, furniture) within each property, including brand, purchase date, supplier, and warranty expiry.

Filtering

Filter properties by name, country, and status. Active filters are shown as removable tags. Use Clear All to reset.

Photo Documentation

Attach up to 5 photos per asset (JPG/PNG, 5MB each). On mobile, use the Take Photo button to capture photos on the spot. Cover thumbnails appear in the asset list and detail header.

Category or Room Grouping

Switch the Asset Manager between category-grouped and room-grouped views with a single click — useful for walkthroughs vs maintenance planning.

Important: Properties marked as Active and Available for Rent are included in vacancy calculations across the system. Make sure your property statuses are kept up to date — stale statuses lead to misleading dashboards.
Understanding the Property List

Each row on the table represents one property. The columns are:

The 7 columns
  • Property — The property name as entered in the system.
  • Country — The country where the property is located (Cyprus, Greece, Spain, etc.).
  • Status — Either Active (included in all calculations) or Inactive (excluded from vacancy and occupancy calculations).
  • Details — Opens the Edit Property form (superuser-only for editing; others see a disabled button).
  • Report — Generates the full Property Details Report (address, specifications, utility accounts, asset summary).
  • Title Deed — Opens the stored title deed PDF in a viewer. Shows "Unavailable" if none has been uploaded.
  • Assets — Opens the Asset Manager for this property. Shows "None" if no assets have been recorded.
Using the filter panel

Click the Property Filters bar at the top to expand filter options. You can filter by:

  • Search Property — free-text search on the property name
  • Country — dropdown with each country represented in your portfolio
  • Status — Active or Inactive

Filters are combinative — all selected filters apply at the same time. Active filter tags appear at the bottom of the panel and can be removed individually, or use Clear All to reset everything.

Map View

Click the Map View button at the top to see all properties as pins on an interactive map. The pins respect the current filter — so if you're filtered to Cyprus only, only Cyprus properties appear on the map. Use Center Map to reset the zoom to show all visible properties.

Tip: For a property to show on the Map View, its address must be correctly geocoded. If a property is missing from the map, open its Edit form and check the map location — you may need to use Find Address on Map to set or correct the pin.
Adding and Editing Properties

Click Add New in the top-right to create a new property, or the Edit button on any row to update an existing one. Both forms contain the same six sections.

1. Property Name

Give it a clear, descriptive name (e.g. "Ionion - Villa 24"). This name appears throughout the system — on the P&L rows, in tenant records, in reports, on maps. A consistent naming convention helps enormously: prefix by building or area, then unit identifier.

2. Address

Fill in the full address — Address Line 1, Address Line 2, Suburb, City, Province, Country, Post Code. A complete address ensures accurate map placement and correctly-rendered reports.

3. Map Location

Two ways to set the pin:

  • Click directly on the map — drops a pin at the clicked location
  • Use "Find Address on Map" — auto-locates the pin based on the address fields you've filled in

Use Clear Location to remove a saved pin. A pin is required for Map View to display the property.

4. Specifications
  • Floor Area (m²) — used for the Rent/m² KPI on Financial Indicators
  • Year Built — informational
  • Include in Occupancy Calculations — Yes means this property counts on Vacancy Management and Performance Trends. Set to No for owner-occupied properties, short-term/summer-let properties, or properties not rented on a traditional basis.
5. Status & Availability
  • Status — Active or Inactive. Inactive properties are hidden from most reports.
  • Available for Rent — Active + Available for Rent + no current tenant = counts as Vacant in Notifications and the Dashboard.
  • Title Deed Available — indicates whether you hold a deed for this property. The actual PDF is uploaded separately.
6. Utility Accounts

Record account numbers and supplier info for:

  • Electricity
  • Water
  • Refuse
  • Property Tax
  • Sewerage
  • Insurance

These appear on the Property Report as a central reference for all service accounts, so you don't have to search through paperwork when a bill arrives or a service needs to be contacted.

Adding vs Editing: The form is identical in both cases — the only difference is that Add New starts blank, while Edit pre-fills every field with the current values. Only Superusers can add properties; Superusers and ordinary users can edit (check the row-level button to see your permission).
Managing Property Assets

Each property can have unlimited assets — appliances, electronics, furniture, and more. Assets are grouped by category in the Asset Manager, and are summarised in the Property Report.

Accessing the Asset Manager

Two ways to open a property's assets:

  • From the Property List — click View in the Assets column (only appears if at least one asset exists)
  • From the Edit form — open the property's Edit form, then click the Assets button in the top-right. This works even if no assets exist yet — it's how you add the first one.
Information recorded per asset
  • Asset Name — e.g. "Samsung Washing Machine"
  • Brand — the manufacturer
  • Category — Appliances, Electronics, Furniture, etc.
  • Subcategory — e.g. Air Conditioner, TV, Sofa
  • Location / Room — e.g. Lounge, Kitchen, Master Bedroom
  • Purchase Date — when the asset was acquired
  • Supplier — where it was bought
  • Warranty Expiry Date — when the warranty ends
Warranty status

Each asset shows one of three warranty badges:

Active — warranty expiry is in the future; the asset is still under warranty.
Expired — warranty expiry is in the past; repairs are now at your cost.
N/A — no warranty expiry date recorded (incomplete data).
Property Report integration: The Property Details Report includes an Asset Summary section showing total asset count, active vs expired warranties, total purchase value, and maintenance cost indicators. Keep assets up to date and the report becomes a powerful portfolio inventory.
Asset Photos & Viewing Options

The Asset Manager supports up to five photos per asset and two different ways of grouping the list. Both features make managing large portfolios with lots of assets much faster.

Category vs Room grouping

By default, assets are grouped by their Category (Appliances, Electronics, Furniture, etc.). Use the toggle buttons at the top of the assets page to switch to Location / Room grouping — useful when you're walking through a property room by room (inventory check, planning a clean, showing a tenant around).

  • Category view — section headers show a tag icon. Best for purchase / maintenance planning.
  • Location / Room view — section headers show a door icon. Best for room-by-room walkthroughs.

The toggle is bookmarkable and refresh-safe — your choice is preserved in the page URL.

Adding photos

When adding a new asset, the Add Asset form includes a Photos field. When editing an existing asset, a dedicated Photos section appears between Purchase Invoice and Notes.

Limits per asset:

  • Up to 5 photos
  • Maximum 5 MB per photo
  • Format: JPG or PNG only

The form enforces these limits before upload — if you pick too many photos or one that's too large, you'll see an inline error before the form submits.

Mobile camera capture: When using a phone or tablet, a green Take Photo button appears next to the file picker. Tap it to open the device camera directly and snap a photo of the asset on the spot — no need to take photos first and upload them later. Use the regular file picker for selecting existing photos from your camera roll.
The cover photo

The first photo in the list is the asset's cover photo — it's the thumbnail shown on the asset list and at the top of the asset detail page. To promote a different photo to cover, open the asset's Edit page and click the star icon on the photo you want as cover.

  • Gold filled star — this is the current cover photo.
  • Grey outline star — click to make this photo the cover.
Deleting photos

On the Edit page, each photo has a red trash icon in its corner. Clicking it shows a confirmation popup before the photo is permanently removed. The deletion is immediate — you don't need to click Save Changes afterwards.

Where photos appear
Asset list rows

Each row in the Asset Manager shows a 50×50 thumbnail of the cover photo before the asset name. Assets with no photos show a placeholder box icon — an at-a-glance reminder of which assets still need documentation.

Asset detail page header

A 60×60 thumbnail of the cover photo replaces the generic briefcase icon at the top of the detail page. Click the thumbnail to open the photo in a full-size lightbox.

Photos card on detail page

When an asset has photos, a dedicated Photos card appears between Asset Info and Warranty on the detail page. Each photo shows as a 160×160 tile (50% width on mobile). Click any tile to open it in a lightbox modal.

Use photos to settle disputes. At handover, photograph each major asset (appliances, electronics, furniture) and add the photo to its record. If a tenant later disputes the condition of an item, the dated record on the asset is the easiest reference to reach for.
Practical Tips
Setting properties up correctly
  • Always set the map location. After entering the address, use Find Address on Map — it auto-places the pin with good accuracy. Properties without a pin won't appear on Map View.
  • Keep statuses up to date. Active + Available for Rent properties with no tenant show as Vacant in Notifications. Stale statuses mislead the whole dashboard — update as soon as a property goes into or out of service.
  • Upload title deeds early. As soon as a deed becomes available, upload the PDF. It creates a secure, centralised home for your legal documents and makes them easy to share with lawyers, tax authorities, or potential buyers.
  • Choose consistent naming. Whatever convention you pick ("Building - Unit", "City-StreetName", etc.), use it for every property. Reports, dropdowns, and filters all work better with predictable names.
Capturing assets properly
  • Record warranty dates when you capture the asset. Once the receipt is filed away, warranty info is easy to forget. Enter it the moment the asset is installed.
  • Use meaningful Location/Room values. "Kitchen" and "Master Bedroom" are much more useful than generic labels when a maintenance engineer needs to know where to go.
  • Keep supplier info. When an item fails, knowing where it was bought (and whether it's still under warranty) saves hours of scrolling through emails.
  • Photograph at handover and on replacement. One or two photos per asset is enough to settle most condition disputes — take them the moment the asset is installed and again when it's replaced. Use the mobile Take Photo button to do this on the spot during a property visit.
  • Promote the best shot to cover. Use the gold star on the Edit page to set the most representative photo as the cover. That's the one tenants and contractors see on the list and the detail header.
Making the module work for you
  • Fill in utility account details. Account numbers for electricity, water, refuse, and other services centralised in one place saves time every time a bill needs to be queried.
  • Use the Property Report regularly. The one-page Property Details Report is the best summary document for meetings with lawyers, accountants, property managers, or tenants. Print or PDF-export before any such meeting.
  • Use Map View for portfolio reviews. Visualising your portfolio geographically can reveal patterns — a cluster of underperforming properties in one area, or over-concentration in a single city.
  • Remember the Include in Occupancy flag. This flag on each property controls whether it appears on Vacancy Management and Performance Trends. Owner-occupied or short-term rentals should be set to No; long-term rentals should be set to Yes.
Properties is the foundation. Every other module in Alivente Online — Tenants, Revenues, Expenses, the P&L, Vacancy Management — builds on the data you capture here. Time spent keeping property records accurate and complete is repaid across the entire system.

Tips and Best Practices
Always upload a scan
A digital copy means you can access documents from anywhere — no need to carry originals for routine reference.
Always enter the expiry date
Without an expiry date the notification system cannot alert you. Always enter it, even for long-validity documents.
Update when documents are renewed
Add the new document record with the new number and expiry date. Consider marking the old one as Inactive rather than deleting to keep a history.
Check red dates before travel
Make it a habit to scan the list before any international travel. Red expiry dates are an immediate visual signal that action is needed.
Use filters for multiple holders
Filter by Holder to view one person's documents at a time. Filter by Type to see all passports or all driver's licences across everyone.
Be careful with Delete
Deleting removes the record and the uploaded file permanently. For old documents, consider setting status to Inactive instead.

How the Notification System Works

The notification system has three layers that all work together to determine who gets notified, about which events, and when.

1
Set up email addresses in Notification Settings
Go to Personal → Notification Settings to register each family member's email address.

TO: Primary recipients — the main people who receive celebration reminders.
CC: Carbon copy recipients — optional additional people to be kept informed.

A family member will never receive a notification unless their email is registered here first.
2
Choose notification timing per event
When adding or editing an event, you set when reminders should be sent under Notification Settings:

Notify 1 week before (sent at 9:00 AM)
Notify 1 day before (sent at 9:00 AM)
Notify same day (sent at 9:00 AM)

You can tick any combination — for example, tick all three for important events like a parent's birthday.
3
Choose who to notify per event ("Notify These People")
Each event has a Notify These People section showing all family members with a tick box next to each name. Tick the family members who have a relationship with this contact and care about this specific event.

For example:
  • A close family member's Nameday → all family ticked → everyone notified
  • A distant colleague's birthday → only one person ticked → only that person notified
The Rule — all three conditions must be met
A family member receives an email notification if and only if:
✓ Their email is registered in Notification Settings
✓ They are ticked in the "Notify These People" section for that event
✓ The notification timing matches (1 week before, 1 day before, or same day)
Fully automatic: Once set up correctly, all notifications are sent automatically at 9:00 AM. No manual action is required on the day.
Tips and Best Practices
Use Excel import to set up quickly
If you have a large contact list, prepare an Excel file with all names and dates and import them in one go. It's much faster than adding contacts one by one.
Add all event types per contact
For Greek contacts, remember to add both their Birthday and Nameday — these are often separate dates. You can add multiple events per contact.
Check the 30-day widget regularly
The dashboard shows upcoming events in the next 30 days. Make it a habit to check it at the start of each month so you can plan ahead for gifts or messages.
Use Timeline View for year planning
The Timeline View shows the entire year ahead chronologically. It's the best way to see "what's coming up" and plan for important occasions months in advance.
Trust the daily email
Once your contacts are set up, the daily email does the work for you. You'll receive a reminder every morning on any day with a celebration — no need to check the system manually.
Use search to find contacts quickly
The search bar on the Celebration Management page filters contacts in real time. Type a name to quickly jump to a specific person and view or edit their events.

What Can I Make?

Click What Can I Make? from the main toolbar. Select the ingredients you currently have at home and the system finds all recipes you can make — ranked by how well your ingredients match each recipe.

Selecting ingredients: Ingredients are grouped by category (Baking, Dairy, Vegetables, Meat, etc.). Click a category header to expand it. Tick individual ingredients or use Select All to tick the whole category. Use the search box to find a specific ingredient quickly.
Automatic inclusions: Herbs, spices, oil, and water are automatically included in every search — you don't need to tick them.
Results: Each matching recipe shows a % match score, how many ingredients you have vs the total, and a list of missing ingredients. Missing proteins are highlighted in red. Click any result to open the full recipe.
Modifying selections: After results are shown, click "Click to modify selections" at the top to go back and adjust your ingredient choices without starting over.

Meal Plans

Creating a Meal Plan: Give it a name and set a start and end date (1–7 days). Then assign recipes to each day and set the number of servings per recipe.

Settings

The Settings dropdown contains five management pages that control how the system handles ingredients, units, conversions and nutrition data — all of which affect shopping list aggregation and the Nutrition Analysis FDA label.

Unit Conversions
Defines how units convert to each other for shopping list consolidation. For example, 1 bag → 4 kg or 1 cup → 240 ml.

Generic conversions apply to all ingredients (e.g. 1 cup = 240ml for any liquid).
Specific conversions apply to one ingredient only (e.g. 1 cup Flour = 125g).

The Missing Conversions button highlights combinations that exist in your recipes but have no conversion defined yet.
Categories
Manages ingredient categories (Baking, Dairy, Vegetables, Meat, etc.). Categories are used to group ingredients in the What Can I Make? selector and on shopping lists. Each category shows how many ingredients use it. You can add, rename, or delete categories.
Units (Measurement Units)
Manages all measurement units available in the recipe editor (cup, tablespoon, gram, kilogram, etc.). Each unit has a singular and plural form, an optional abbreviation, and a type: Weight, Volume, Count, or Other. The type determines rounding behaviour in shopping lists.
Ingredients (Shopping Units)
Sets the preferred shopping unit for specific ingredients. When a shopping list is generated, ingredients with a defined shopping unit are displayed in that unit (e.g. Butter always shown in grams, Garlic always in cloves). This ensures shopping lists are presented in the most practical unit for each ingredient.
Map Ingredients to Nutrition
Links each ingredient to a USDA FoodData Central record so that the Nutrition Analysis FDA label can compute calories, fat, carbs, fibre, sugar and protein. Ingredients without a nutrition mapping show a yellow Not mapped badge in the recipe nutrition modal.

Two ways to provide nutrition data:
USDA lookup — search the USDA database, preview the nutrition values, and map them to the ingredient. The standard option for common ingredients.
Manual entry — type in your own per-100g values when an ingredient isn't in the USDA database (or when the USDA values don't match your specific brand or preparation). Manually-entered ingredients display a yellow "M" pill on the Mapped badge so you can tell them apart from USDA-sourced data at a glance.
A Reset to USDA values button is available on any ingredient with manual entries, in case you want to discard your manual values and revert to the original USDA mapping.
Note: These settings affect how shopping lists are calculated, how units are aggregated, and how nutrition values are derived. If your shopping list shows unexpected quantities, check Unit Conversions for missing or incorrect rules. If a recipe's Nutrition Analysis label is incomplete, check Map Ingredients to Nutrition for unmapped ingredients.

A Fully Furnished shortcut checkbox sits at the top right of the section — useful when the property includes the standard fully-furnished bundle.

Keys Provided

Quantity inputs for Apartment Building Key, Apartment Front Door Key, Storeroom Key and Post Box Key. Records what physical keys are handed to the tenant.

Save & Continue validates every required field. If anything is missing you'll get a popup telling you which field — the modal stays open until everything checks out, at which point Step 3 unlocks.
Individual vs Company tenants

Tenants come in two types. The data the system needs differs for each.

Individual

Required fields: Passport/ID Number, Passport/ID Country, plus standard contact details.

Second tenant: Allowed. The + Add Second Tenant button appears in the Tenant Information panel.

Company

Required fields: Company Registration Number, Contact Person, plus standard contact details.

Second tenant: NOT allowed. The Add Second Tenant button is hidden for Company tenants.

Second Tenant rules
  • Individual tenants only — you cannot add a second tenant to a Company-type primary tenant.
  • Second tenants are always treated as Individuals (no Company option).
  • All fields required — name, passport/ID, email, phone, address.
  • Click the Remove button on the green Second Tenant header to clear it — all fields are reset.
Switching from Individual to Company: If you have a second tenant added and try to change the primary tenant type to Company, the system blocks the switch and asks you to remove the second tenant first.
Best Practices
  • Have everything ready before starting — passport numbers, monthly rent, deposit amount, dates. The wizard validates every required field before allowing Save.
  • Double-check the Country — it filters which properties appear in Step 2 and which language template gets used. Choose wrong and you'll see no properties.
  • Review the Selected Data Preview — before clicking Review & Complete Data, sanity-check that the property and tenant on screen are the right ones.
  • Use 0 for "not applicable" — Communal Expenses, Extension Period and Rental Increase all need a number. Enter 0 rather than leaving them blank.
  • Extension Date auto-calculates — the field updates whenever you change End Date or Extension Period. You can't edit it manually.
  • Update Landlord defaults if your standard landlord changes — the pre-filled Alivente Limited details apply unless you overwrite them per lease.
  • Furniture quantities cap at 9 — if you somehow have 10 of something, record it as 9 and add a note to the property file.
  • Validation alerts pause the flow — if Save & Continue throws an alert about a missing field, the modal stays open. Fix the field and try again.
  • Once generated, manage it elsewhere — the generated lease shows up under Manage Lease Agreements. Use that page to view, replace or delete the document later.
  • Generating creates the tenant if "+ New Tenant" was used — the new tenant record is added to your system as part of the generation, not before.
Generate button stuck disabled? All four conditions must be true: Country selected, Language selected, Property selected, Tenant selected, AND the Save & Continue step in the data modal completed without validation errors. If any one is missing, the button stays grey.
What is User Administration?

User Administration is the central place to manage everyone who can log into Alivente Online. From this single screen you can:

  • Add new users
  • Edit existing user details (name, email, role, password)
  • Manage permissions — grant or revoke access to individual modules
  • Disable users so they can no longer log in (without losing their data)
  • Re-enable previously disabled users
  • Delete users permanently (only available once disabled)
How to get here

Administration System tab User Administration card.

Superuser only: User Administration sits inside the Administration page, which is itself Superuser-only. Regular users cannot reach this screen.
The user table

Every registered user appears as one row, with six columns:

User

A circular avatar (uploaded photo if available, otherwise the user's initials, or as a final fallback the first letter of the username), the user's full name, and their email address. "No email" is shown if none was set.

Role

A coloured badge: Superuser or User. See the Roles tab for what each one means.

Status

Active — can log in. Disabled — account exists but login is blocked.

Last Login

Date and time of the user's most recent login. Shows Never in grey if they've never signed in.

Date Joined

When the user account was originally created.

Actions

A row of small coloured buttons. The button set changes depending on whether the user is Active or Disabled — see the Actions tab.

The two roles

Every user has one role, shown as a coloured badge in the User table.

Superuser

Full administrative access. Superusers automatically have access to every module — the Permissions screen for a Superuser is informational only and any module checkboxes are ignored. Use sparingly — this role can do everything, including managing other users.

User

Standard access — the default role for new accounts. Module access is fully controlled by the Permissions screen.

Choosing a role: Default everyone to User and grant only the modules they need via Permissions. Reserve Superuser for the small number of people who genuinely need to administer the whole system.
Available actions

One header action and a set of per-user row actions.

Add User (top-right)

Opens the Add New User form, which collects:

  • Personal Information — First Name, Last Name, Username (required), Email Address
  • Password — Password and Confirm Password (must match)
  • Role & Status — pick User or Superuser, and tick Active so they can log in immediately
Per-user row actions
Edit (yellow)

Update the user's name, email, role or password. Always available regardless of status.

Permissions (teal)

Opens the Permissions screen, where you tick which of the 12 modules the user can access (Properties, Tenants, Suppliers, Expenses, Petty Cash, Financials, Invoices, Projects, Issues, Dashboard, Administration, Personal).

Superusers automatically get all 12 — the checkboxes are read-only for Superuser accounts.

Disable (red, only for Active users)

Blocks the user from logging in. Their account and data remain intact — nothing is lost. A confirmation popup asks you to confirm before applying.

Enable (green, only for Disabled users)

Restores login access for a previously disabled user. Replaces the Disable button on disabled rows.

Delete (red, only for Disabled users)

Permanently removes the user and all their associated data — meal plans, favourites and any other records. Cannot be undone.

Only available for users who are already disabled. The two-step requirement (Disable first, then Delete) is intentional — it forces a deliberate pause before destructive action.

Action button visibility: Active users show Edit, Permissions, Disable. Disabled users show Edit, Permissions, Enable, Delete.
Best Practices
  • Disable rather than delete — if someone leaves the team, disable their account. You can always re-enable later if they come back. Delete only when you're certain you'll never need their historical activity.
  • Default new users to "User" — grant least privilege. Add only the modules they need via Permissions. Promote to Superuser only when justified.
  • Be sparing with Superuser — this role bypasses the Permissions screen entirely. The fewer Superusers, the safer your system.
  • Watch for "Never" Last Login — an account that has never logged in is either a failed setup, a forgotten invitation, or a placeholder. Confirm it's intentional or chase the person to log in.
  • Email is important — it's where notifications go. Always set a real email when creating a user. "No email" accounts won't receive any system alerts.
  • Don't bother editing Superuser permissions — they're ignored. The Permissions screen for Superusers is read-only.
  • Use the avatar as a quick visual cue — users with profile photos appear immediately recognisable. Encourage your team to upload one in My Profile.
  • Test permission changes by logging in as that user — the cleanest way to confirm someone has the access you intended is to actually try it.
Don't disable yourself! If you disable your own account you'll be locked out at next login. There's no built-in protection against this — double-check the username before clicking Disable on yourself.

What are Revenue Types?

A Revenue Type defines the seasonality pattern of an income stream — in other words, which months of the year that income is actually collected.

Each Revenue Type is essentially a 12-month template made up of Yes/No flags. When you later create a Revenue record on a property and assign it a Revenue Type, the system uses this template to know when to count that income across the calendar year.

Two examples already in your system:
  • Monthly — all 12 months marked Yes. Use this for standard year-round rentals or any income collected every month.
  • Summer — May to October marked Yes, the rest No. Use this for seasonal lets, holiday rentals, or anything only earning in the summer months.
Where this fits in the bigger picture

Revenue Types are one of three Configuration pieces on the Revenue side that work together:

  1. Revenue Types (this page) — when income is collected (the months pattern)
  2. Revenue Line Types — what the income is called on the P&L (e.g. "Rental", "Levies")
  3. Revenues — the actual records: a property + a Line Type + a Type + an amount

Together these feed into the Profit & Loss Statement, where each month's revenue is calculated by applying the Type's pattern to the Revenue amounts on each property.

Permissions: This page is restricted to Superusers. Standard users won't see Configuration in the Financials menu.
Reading the Table

Each row is a Revenue Type you've defined. The 12 month columns show, at a glance, which months that Type collects income.

Column-by-column
  • Revenue Type — the name you gave it (e.g. Monthly, Summer).
  • Jan – Dec — one column per month, showing either Yes or No.
  • Details — an Edit button to modify that Revenue Type.
The colour coding

The cells are colour-coded to make seasonality patterns easy to spot at a glance:

  • Green — Yes   income is collected this month
  • Red — No   income is not collected this month
At a glance: A row that's all green is a year-round income pattern. A row with a clear green block flanked by red shows a seasonal pattern — like the Summer row, where you can immediately see income runs from May through October.
Adding a Revenue Type

Click Add New in the top-right to open the Add Revenue Type form. You'll see two things to fill in:

  1. Revenue Type Name — a short, descriptive name (e.g. Monthly, Summer, Winter, Quarterly).
  2. The 12-month checkbox grid — one checkbox per month.
How the checkboxes map to Yes / No:
  • Checked  =  income IS collected that month  →  saved as Yes
  • Unchecked  =  income is NOT collected that month  →  saved as No

The Add form doesn't show "Yes/No" labels — just the checkboxes. The conversion happens automatically when you save.

When you're done, click Save in the top-right. The Type appears in the list and is immediately available to assign to Revenue records.

Editing an existing Revenue Type

Click the Edit button on the relevant row. The form is identical to the Add form — the Name field is pre-filled, and the checkboxes reflect the current Yes/No pattern. Make your changes and click Save.

Editing has a downstream effect. If a Revenue Type is already in use by Revenue records on properties, changing its month pattern will retroactively change how those records appear in the Profit & Loss Statement. For example, switching Summer from May–Oct to Apr–Sep will shift every revenue record using Summer by one month in the P&L. If you need a different pattern, consider creating a new Revenue Type rather than editing an existing one.
Practical Tips
  • Name them by pattern, not by property. A Revenue Type is reused across many properties — Monthly, Summer, Quarterly all describe patterns. Avoid names like "Apolloneon Rental"; that belongs on the Revenue record itself, not the Type.
  • Start simple. Most portfolios only need two or three Types: Monthly covers nearly everything; add Summer (or Winter) for seasonal lets. Don't create a Type until you have a property that actually needs it.
  • Keep Monthly as your default. It's the most common pattern, and having it always available means you rarely have to think about Type selection when adding routine revenue.
  • Plan around your local seasons. "Summer" means different months in different countries — for Cyprus and Greece holiday lets, May to October is typical. Set the pattern based on when income actually arrives, not on calendar quarters.
  • Don't edit Types in active use — clone them instead. Editing changes the P&L for every Revenue record using that Type, retroactively. Safer pattern: create a new Type with the new shape (e.g. Summer 2026), then move the affected Revenue records to it one at a time.
  • Use the colour bands to sanity-check. After saving, glance at the row in the table. If Summer shows green in December, something's wrong — the visual makes mistakes easy to spot.
  • The Type doesn't store amounts — only the months. The actual € figure lives on the Revenue record. Two properties can both use Monthly with completely different rents.
Next step: Once your Revenue Types are set up, head to Revenue Line Types to define what the income is called (e.g. Rental, Levies), and then Revenues to record the actual amounts on each property.
What are Revenue Line Types?

A Revenue Line Type defines the category of an income stream — the label that will appear as a row in the Revenue section of the Profit & Loss Statement.

Where Revenue Types describe when income is collected (the months pattern), Revenue Line Types describe what the income actually is. They're the answer to: "What kind of income is this?"

Two examples already in your system:
  • Rental — "Rental Income" (the rent paid by tenants)
  • Levies — "Levies" (building/community levies recovered from tenants)

These are the two rows you'll currently see in the Revenue section of the P&L for any property.

Where this fits in the bigger picture

Revenue Line Types are the second piece of the three-part Revenue configuration:

  1. Revenue Types — when income is collected (the months pattern)
  2. Revenue Line Types (this page) — what the income is called on the P&L
  3. Revenues — the actual records: a property + a Line Type + a Type + an amount

Every Revenue record on every property must be tagged with a Line Type. The P&L then groups all matching records together to produce a single Revenue row labelled with that Line Type's name.

Permissions: This page is restricted to Superusers. Standard users won't see Configuration in the Financials menu.
Reading the Table

The table is intentionally simple — each row is one Line Type with three columns:

  • Revenue Line Type — the short name. This is what shows up as the row label in the P&L (e.g. Rental, Levies).
  • Revenue Line Type Description — a longer, human-readable description. Currently this is for your own reference; the P&L uses the short name only.
  • Details — an Edit button to modify the Line Type.
What you see here = what shows up in the P&L. If your table has rows for Rental and Levies, your P&L Revenue section will have a row for each. Add a third Line Type (e.g. Parking), and as soon as a Revenue record is tagged with it, a third row will appear in the P&L.
Adding a Revenue Line Type

Click Add New in the top-right to open the Add Line Type form. There are just two fields:

  1. Revenue Line Type Name — the short label. This is what appears in the P&L, so keep it short and clear (e.g. Rental, Levies, Parking, Storage).
  2. Revenue Line Type Description — a longer explanation for your own records (e.g. "Monthly rent paid by tenants").

Click Save in the top-right. The new Line Type appears in the list and is immediately available to assign to Revenue records.

Editing an existing Revenue Line Type

Click the Edit button on the relevant row. The form is identical to the Add form, with both fields pre-filled. Update either field and click Save.

Renaming has a downstream effect. If you change the Name of a Line Type that's already in use, the row in the Profit & Loss Statement will immediately show the new name — including for all historical periods. The underlying numbers don't change, only the label. This is usually fine (e.g. tidying up a typo), but be aware that older P&L screenshots will no longer match the live page.
Don't repurpose a Line Type. If you want a new income category, create a new Line Type. Don't rename Rental to Parking — every existing Revenue record tagged as Rental will suddenly be reclassified as Parking in the P&L.
Practical Tips
  • Keep names short. The Name appears in P&L tables where space is tight — one or two words is ideal (Rental, Levies, Parking). Save the longer wording for the Description field.
  • Use the Description field generously. It's free-form and only visible here, so use it to capture the full meaning — especially for Line Types where the short name might be ambiguous later.
  • Think about how you want the P&L to read. Each Line Type becomes a row in the Revenue section. If you want Rental and Parking as separate rows in the P&L, create them as separate Line Types. If you want them combined into a single Rental row, just use one Line Type and tag both kinds of revenue with it.
  • Don't over-categorise. Two or three Line Types is enough for most portfolios. Adding too many produces a fragmented P&L where every row is small, making the bigger picture harder to read.
  • Be consistent across properties. If one property's monthly rent is tagged Rental and another's is tagged Rent Income, they'll appear as two different rows in the consolidated P&L. Pick one name and stick with it.
  • Plan for new income streams. If you start charging tenants for parking, storage, or utilities separately, add a Line Type before adding the first Revenue record — that way the P&L category is ready when the income starts flowing in.

What is a Revenue record?

A Revenue record is a single income stream for a single property. It's where everything from Configuration finally comes together to describe a real-world income source — for example, "Apolloneon-Demetri earns €800 in monthly rent".

Each Revenue record is built from four pieces:

  1. Property — which property generates this income
  2. Revenue Line Type — what the income is (e.g. Rental, Levies)  →  becomes the row label in the P&L
  3. Revenue Type — when it's collected (e.g. Monthly, Summer)  →  controls which months the amount is counted
  4. Revenue Amount — how much (in euros) is collected per active month
A worked example

Looking at the table now — Apolloneon-Demetri has two Revenue records:

  • Rental / Monthly / €800  →  €800 of rental income every month, all year.
  • Levies / Monthly / €30  →  €30 of levy income every month, all year.

Together these give the property an annual income of (€800 × 12) + (€30 × 12) = €9,960, made up of €9,600 Rental + €360 Levies.

Where this fits

This is the final piece of the three-part Revenue configuration:

  1. Revenue Types — when income is collected (the months pattern)
  2. Revenue Line Types — what the income is called on the P&L
  3. Revenues (this page) — the actual records on each property

If you haven't set up Types and Line Types yet, do those first — the dropdowns on the Add Revenue form are populated from them.

Permissions: This page is restricted to Superusers.
Reading the Table

Records are grouped by property and presented as a list of collapsible rows — one row per property, with the records hidden inside until you expand the row.

Property header rows

Each property appears as a single bold row with three things:

  •  A chevron arrow on the left — right-pointing when collapsed, down-pointing when expanded.
  • The property name.
  • A teal 2 count badge showing how many Revenue records that property has.
Expanding and collapsing
  • Click a property header to expand it. The chevron rotates down and the records appear below.
  • Click the same header again to collapse it.
  • Click a different property's header and the previously-open one auto-collapses — only one property can be open at a time. This keeps the page tidy when you have many properties.
Inside each property

One row per Revenue record, with five columns:

  • Property — the property name (repeated for clarity).
  • Revenue Line Type — the category (e.g. Rental, Levies).
  • Revenue Type — the months pattern (e.g. Monthly, Summer).
  • Revenue Amount — the euro amount per active month, formatted with thousand separators (e.g. € 800, € 1,250).
  • Details — an Edit button to modify that record.
Properties without revenue records don't appear here. If a property is missing from the list, it has no Revenue records yet — click Add New to create one for it.
Adding a Revenue record

Click Add New in the top-right to open the Add Revenue form. You'll see four fields in a row:

  1. Property — dropdown of all your active properties. Pick the one this income belongs to.
  2. Revenue Line Type — dropdown populated from the Revenue Line Types page (e.g. Rental, Levies).
  3. Revenue Type — dropdown populated from the Revenue Types page (e.g. Monthly, Summer).
  4. Revenue Amount — the euro amount collected per active month (a numeric value, no currency symbol needed).

Click Save in the top-right and the new record appears in the property's group on the listing page.

The amount is per active month, not per year. If a property earns €800 in monthly rent, enter 800 — not 9,600. The system multiplies by the months your chosen Type marks as active. So €800 paired with Monthly = €9,600/year, but €800 paired with Summer (May–Oct) = €4,800/year.
One record per income stream

If a property has multiple income streams — rent, levies, parking, storage — create a separate Revenue record for each. This keeps the P&L breakdown by Line Type meaningful and makes it easy to track each income stream independently.

Editing an existing Revenue record

Expand the property's row, then click the Edit button on the relevant record. The form is identical to the Add form, with all four fields pre-filled. Update what you need and click Save.

Edits affect the P&L immediately — including history. Revenue records aren't dated — they describe an ongoing pattern. Changing the amount from €800 to €900 instantly recalculates the P&L for every month, every year, including past periods. If you need to capture a rent increase mid-year while preserving history, the cleanest approach is to delete-and-recreate, or simply note the change date externally.
How Revenue records build the Profit & Loss Statement

The P&L doesn't store revenue numbers — it calculates them every time you open it, by walking through your Revenue records and applying a simple three-step formula.

The formula
  1. For each Revenue record → look up its Revenue Type to see which months are active.
  2. For each active month → the record contributes its amount to that month.
  3. For each month → group all contributions by Revenue Line Type → that's the row in the P&L Revenue section.
A worked example with two properties

Suppose you have:

  • Property A: Rental / Monthly / €800   +   Levies / Monthly / €30
  • Property B: Rental / Summer / €1,000

Step through the months:

  • January — Property A pays €800 rental + €30 levies. Property B pays €0 (Summer doesn't include January).
  • June — Property A pays €800 + €30. Property B pays €1,000.
  • December — Property A pays €800 + €30. Property B pays €0.

Now group by Line Type for each month and you get:

  • Rental row: €800 (Jan), €800 (Feb), …, €1,800 (May–Oct), …, €800 (Dec)  →  total €15,600/year
  • Levies row: €30 every month  →  total €360/year
The P&L is fully derived. Every revenue figure on the P&L can be traced back to a specific Revenue record on this page. If a number on the P&L looks wrong, the answer is always somewhere here — either an incorrect amount, the wrong Type assigned, or a missing record.
Drilling down from the P&L

On the P&L Statement, every blue revenue number is clickable. Clicking it opens a breakdown showing exactly which properties contributed to that figure — making it easy to trace any value back to the underlying records.

Practical Tips
  • Set up Configuration first. Revenue Types and Revenue Line Types must exist before you can create a Revenue record — the dropdowns won't have anything to pick. If you're starting from scratch, create at least Monthly (Type) and Rental (Line Type) before coming here.
  • One record per income stream per property. If a property earns rent and levies, create two records, not one combined one. The P&L groups by Line Type, so combined records lose the breakdown.
  • Enter the per-month amount, not the annual. The most common new-user mistake is entering €9,600 (the yearly figure) for a €800/month rental. The Type handles the multiplication — just enter 800.
  • Match the Type to reality. If a property is rented year-round, use Monthly. If it's a holiday let active May–Oct, use Summer. The wrong Type produces a P&L that doesn't match what's actually happening.
  • Use the Edit button for changes, not delete-then-recreate. Editing preserves the record's identity and is the right tool for amount adjustments, Type changes, or fixing typos. Delete-and-recreate is only needed if you want to break P&L history for that record.
  • Be aware that edits change history. Revenue records describe an ongoing pattern, not a dated transaction. Changing the amount today instantly rewrites the P&L for past months too. If you need a true dated change (e.g. rent increased on 1 July), keep external notes — the system shows the current state only.
  • Check the count badge. The teal number next to each property name tells you how many Revenue records it has. A property showing 1 when you'd expect 2 (rent + levies) is a quick visual flag that something's missing.
  • Properties with no records don't show. If a property is missing from the list entirely, it has zero Revenue records — meaning it currently contributes €0 to the P&L. This is usually a bug to fix, not a feature.
  • If a P&L number looks wrong, start here. Every revenue figure on the P&L is calculated from the records on this page. There are no other inputs — so if something looks off, expand the relevant property and check the records.
Next step: With Revenues set up, your P&L will show the income side of the picture. To complete it, head to the Expense side — Expense Types, Expense Line Types, and Expenses — which work the same way.
What are Expense Types?

An Expense Type defines the timing pattern of an expense — which months of the year that expense is actually paid.

Each Expense Type is a 12-month template made up of Yes/No flags. When you later create an Expense record on a property and assign it an Expense Type, the system uses this template to know when to count that expense across the calendar year.

Compared with Revenue Types, the Expense side has more variety — because real-world expenses come in many shapes: monthly bills, quarterly utility charges, semi-annual taxes, and one-off annual payments that hit in a specific month.

Three families of pattern
1. Recurring — multiple months a year
  • Monthly — all 12 months. For Property Manager fees, recurring service charges.
  • Quarterly — Jan, Apr, Jul, Oct. For utilities billed every 3 months.
  • Six Monthly — Jan + Jul. For semi-annual obligations.
  • Summer Monthly, Summer Bi-Monthly — for seasonal recurring costs (cleaning, garden maintenance, etc.).
2. One-off — a specific month, once a year
  • January, February, March, … December — one Type per month, with that single month flagged Yes. Use these for annual bills that hit at a fixed time of year.
  • Example: Company Tax paid every June → assign the June Expense Type.
  • Example: Insurance renewing every September → assign the September Expense Type.
3. Property-specific custom patterns
  • Build whatever pattern you need — e.g. a property charging communal fees in March + September only would need a Type with just those two months flagged Yes.
Where this fits in the bigger picture

Expense Types are one of three Configuration pieces on the Expense side that work together (mirror of the Revenue side):

  1. Expense Types (this page) — when the expense is paid (the months pattern)
  2. Expense Line Types — what the expense is called on the P&L (e.g. Property Manager, Insurance (Cyprus))
  3. Expenses — the actual records: a property + a Line Type + a Type + an amount

Together they feed into the Profit & Loss Statement, where each month's expenses are calculated by applying each Type's pattern to its Expense amounts.

Practical Tips
  • Pre-build the 12 single-month Types. Most portfolios will eventually need January, February, … December — one Type per month for annual bills. Building all 12 once means you'll always have the right one ready when you create an Expense.
  • Name single-month Types after the month itself. Calling them June, September, etc. makes them self-documenting. The user creating an Expense record sees the Type name and immediately knows the bill hits in that month.
  • Don't bake the property name into a Type. A Type is reused across many properties. Quarterly works for any property paying quarterly; avoid names like "Eleftheroupoleos Schedule".
  • Match the Type to the bill, not to your accounting cycle. If utilities arrive on a Mar/Jun/Sep/Dec rotation, build a Type with exactly those months flagged. The P&L should reflect when money actually goes out, not how you'd prefer to spread it.
  • For annual bills, single-month Types beat “Annual”. A generic Annual Type (with one month flagged) becomes ambiguous — which month? Twelve named single-month Types remove the ambiguity entirely.
  • Don't edit Types in active use — clone them instead. Editing changes the P&L for every Expense record using that Type, retroactively. Safer pattern: create a new Type with the new shape, then move the affected Expense records to it one at a time.
  • The Type doesn't store amounts — only the months. The actual € figure lives on the Expense record. Two properties can both use Monthly for Property Manager with different fees.
  • Use the colour bands to sanity-check after saving. A glance at the row tells you whether the pattern is what you intended — misclicked checkboxes show up immediately.

What are Expense Line Types?

An Expense Line Type defines the category of an expense — the label that will appear as a row in the Expenses section of the Profit & Loss Statement.

Where Expense Types describe when an expense is paid (the months pattern), Expense Line Types describe what the expense actually is. They're the answer to: "What category of expense is this?"

Examples already in your system

Your Line Types fall into a few clear groupings:

  • Standard recurring expenses — Property Manager, Cleaning Costs, Garden Maint., Electricity, Refuse, Sewerage
  • Country-specific tax/professional fees — Financials (Cyprus), Financials (Greece), Financials (Spain), Insurance (Cyprus), Prop Tax (Cyprus)
  • Multi-instance recurring — Communal Fees 1, Communal Fees 2 (one Line Type per payment instance — see Tips for why)
  • Pro-Rata expenses — covered in their own tab
Where this fits
  1. Expense Types — when the expense is paid
  2. Expense Line Types (this page) — what the expense is called on the P&L
  3. Expenses — the actual records: a property + a Line Type + a Type + an amount
What's different from Revenue Line Types

Two important differences worth noting up front:

  • You can delete an Expense Line Type (Revenue Line Types are Edit-only). The Delete button does a smart cascade check — see The Table tab.
  • An Expense Line Type can be marked Pro-Rata — meaning a single bill covering multiple properties is automatically split across them. See the Pro-Rata Explained tab for the full picture.

  • Expense Line Type — the short name. This is what appears as the row label in the P&L.
  • Expense Line Type Description — a longer, human-readable explanation. Currently for your reference only; the P&L uses the short name.
  • Actions — an Edit button (light/grey) and a Delete button (red).
The Edit button

Opens the same form as Add New, with the four fields pre-filled (Name, Description, Pro-Rata Yes/No, Pro-Rata Amount). Make changes and click Save.

The Delete button — the cascade check

Clicking Delete doesn't immediately remove anything. Instead it opens a Confirm Delete modal that first scans the database for any Expense records using this Line Type:

  • If nothing is using it → you see a simple "Are you sure?" prompt. Click Delete to confirm.
  • If Expense records exist → you see the full list of every record that will also be deleted, with each entry showing: Expense ID, the property it belongs to, the Type assigned, the base amount, the total monthly amount, and a month-by-month breakdown.
Cascade delete is permanent. Confirming the delete removes the Line Type and every linked Expense record across all properties. The deleted records cannot be recovered — you'd have to re-create each one manually. Read the linked-expenses list carefully before clicking Delete the second time.
The detail view is your safety net. If you see records you weren't expecting (e.g. a Pro-Rata Line Type with 10 linked expenses you'd forgotten about), the modal lets you abort before any damage is done. Always glance through the list first.
Adding an Expense Line Type

Click Add New in the top-right. The form has four fields:

  1. Expense Line Type Name — the short label that will appear in the P&L (e.g. Property Manager, Insurance (Cyprus)).
  2. Expense Line Type Description — the longer explanation for your records (e.g. "Monthly property management fee").
  3. Pro-Rata (Yes/No) — defaults to "Select an option". Choose Yes only if this Line Type represents a single bill that should be split across multiple properties.
  4. Pro-Rata Amount — only used when Pro-Rata is set to Yes. Enter the total annual amount of the bill (e.g. 2810 for an annual €2,810 audit fee). Leave at 0 if Pro-Rata = No.

Click Save. The new Line Type appears in the list and is immediately available to assign to Expense records.

When should I set Pro-Rata = Yes?

Set Pro-Rata to Yes when:

  • You receive one invoice that covers multiple properties (e.g. an audit firm bills you €2,810 for the whole Cyprus portfolio).
  • You want the cost split fairly across those properties (proportional to each property's Current Value), not arbitrarily.
  • Each property should end up with its own Expense record showing its share, but you only want to enter the bill once.

Set Pro-Rata to No when each property's expense is captured individually — for example, each property has its own electricity bill at its own amount.

Editing an existing Line Type

Click the Edit button on the relevant row. The form is identical, with all four fields pre-filled. Update what you need and click Save.

Renaming changes the P&L label immediately — including for all historical periods. The numbers don't change, only the label. Older P&L screenshots will no longer match the live page.
Don't repurpose a Line Type. If you want a different category, create a new Line Type. Don't rename Electricity to Water — every existing Expense record tagged as Electricity will instantly be reclassified as Water in the P&L.
Changing the Pro-Rata Amount triggers a live preview and cascade. When you change the Pro-Rata Amount on a Line Type that has linked Expense records (e.g. €2,810 → €3,000) and click Save, the system intercepts with a preview modal showing exactly what will happen:
  • Every linked Expense record is listed with its Old Amount / New Amount / Δ
  • Red Δ values indicate properties that will pay more; green Δ values indicate properties that will pay less
  • Clicking Save & Recalculate All saves the Line Type and updates every linked Expense record in one atomic operation
  • Clicking Cancel aborts — nothing is saved

No more manual trips to the Expenses page — the cascade happens in a single click.

What is a Pro-Rata Expense?

A Pro-Rata Expense is a single bill that legitimately covers multiple properties, and that should be fairly split across them rather than dumped on one.

Classic examples:

  • Audit fees — the auditor charges €2,810 to audit your whole Cyprus portfolio. That's not "Eleftheroupoleos's expense" — it should be shared across all the audited properties.
  • Annual company fees — a single fee that supports the whole legal entity owning multiple properties.
  • Country-wide insurance — a master policy covering all properties in one country.
  • Professional services — legal, tax preparation, consulting that benefits the portfolio rather than any one property.
How Pro-Rata works in two stages
Stage 1 — Setup (here, on the Line Type)
  • Set Pro-Rata = Yes
  • Enter the total annual bill in Pro-Rata Amount (e.g. €2,810)
  • Save
Stage 2 — Capture (on the Expenses page)
  • Create an Expense record for any one of the affected properties
  • Pick the Pro-Rata Line Type — the Expense Amount is auto-filled with the total (€2,810) and locked
  • A property selection panel appears, with the current property auto-checked and locked-in
  • Tick the other properties this bill covers (or use the Country quick-filter to tick them all in one click)
  • Click Calculate Pro-Rata Amounts — a Pro-Rata Expense Preview modal opens showing the proposed split: each selected property with its Current Value, percentage Share, and calculated Amount
  • Review the preview — if the split looks right, click Confirm & Update; if not, click Cancel and adjust your property selection
  • On confirmation, the system creates new Expense records on the other properties (or updates existing ones) with each property's calculated share
A worked example

Audit fee: €2,810 total. Three Cyprus properties selected, with their Current Values:

  • Property A — Current Value €200,000
  • Property B — Current Value €800,000
  • Property C — Current Value €320,000

Total combined value = €1,320,000. The split:

  • Property A: 200,000 ÷ 1,320,000 × €2,810 = €426
  • Property B: 800,000 ÷ 1,320,000 × €2,810 = €1,703
  • Property C: 320,000 ÷ 1,320,000 × €2,810 = €681

The system creates/updates three Expense records, one per property, with these amounts. The P&L for Financials (Cyprus) then shows the correct share against each property.

Things to know about the distribution
  • Current Value drives the split — higher-valued properties bear a bigger share, lower-valued properties less. Each property's Current Value is set on the Property record (under Properties → Edit) and is shown next to each checkbox in the property selection panel.
  • The current property is always included — you can't un-tick the property you're capturing the expense for, since you're creating its record.
  • The Country filter is a tickbox shortcut — selecting "Cyprus" auto-ticks all Cyprus properties. You can still un-tick individual ones afterwards if a property shouldn't be included.
  • Existing Expense records are updated, not duplicated — if Property B already had a Financials (Cyprus) Expense from a previous round, its amount is overwritten by the new calculation, not added on top.
Things to be careful with
  • Changing the Pro-Rata Amount on the Line Type cascades automatically — with a preview. If you bump €2,810 to €3,000 on the Line Type page, clicking Save opens a preview modal showing the full before/after per-property breakdown. Confirming with Save & Recalculate All commits both the new Line Type amount and the redistributed Expense records in one atomic operation — no separate trip to the Expenses page needed.
  • Adding a new property to the portfolio doesn't auto-include it. Existing Pro-Rata Expense records won't pick up the new property. Open the Expense record on any one of the existing properties, tick the new one in the panel, and re-calculate.
  • Deleting a Pro-Rata Line Type cascades hard. Every Expense record on every property using this Line Type is deleted. The Confirm Delete modal lists all of them — read carefully.
Practical Tips
Naming & structure
  • Keep Names short. The Name appears in P&L tables where space is tight — one or two words is ideal. Use the Description for the longer wording.
  • Suffix country into the Name when needed. If you have audit fees in multiple jurisdictions, name them Financials (Cyprus), Financials (Greece), Financials (Spain) — not just Financials three times. Each becomes its own row in the P&L, which is exactly what you want for country-by-country tax reporting.
  • Be consistent. If one property's electricity is tagged Electricity and another's is tagged Power, they'll appear as two different rows in the P&L. Pick one name and stick with it.
  • Don't over-categorise. Too many Line Types fragments the P&L into a long list of tiny rows. Combine related minor expenses (e.g. don't split Bin Bags from Cleaning Products — both are Cleaning Costs).
The "Communal Fees 1, 2, 3..." pattern

You'll notice some Line Types are numbered (Communal Fees 1, Communal Fees 2). This is a deliberate workaround for a real limitation:

The problem: A single Expense record stores one amount. So you can't say "€340 in January and €270 in July" with a single record — the two payments have different amounts.

The solution: Split the conceptual Communal Fees into numbered Line Types — one per payment instance. Pair each with a single-month Expense Type:

  • Communal Fees 1 + January Expense Type + €340
  • Communal Fees 2 + July Expense Type + €270

Properties with different schedules (annual, semi-annual, quarterly) coexist nicely because each one only uses the subset of numbered Line Types it needs.

Working with Pro-Rata
  • Only mark Line Types as Pro-Rata when there's truly one bill. If each property has its own Insurance bill (different amounts, paid separately), don't use Pro-Rata — just create individual Expense records. Pro-Rata is for the "one invoice, many properties" scenario.
  • Re-run Calculate when adding/removing properties. The distribution doesn't auto-update when the property pool changes. After acquiring or selling a property, open any one of the Pro-Rata Expense records, adjust the property panel, and re-calculate.
  • Pro-Rata Amount changes cascade automatically. When you change the Pro-Rata Amount on a Line Type with linked Expense records, the system shows a preview modal with the full per-property impact (old/new/Δ). Confirming with Save & Recalculate All saves the Line Type and pushes the new distribution through every linked Expense record in one operation.
Working with Delete
  • Always read the cascade list. The Confirm Delete modal shows every linked Expense that will be destroyed. For Pro-Rata Line Types this can be 10+ records across multiple properties — well worth a slow review.
  • Don't delete to "fix a typo". Use Edit to rename. Delete is for retiring a Line Type entirely — e.g. an expense category you no longer have at all.

What is an Expense record?

An Expense record is a single budgeted expense for a single property. It's where everything from Configuration finally comes together to describe a real-world cost — for example, "Eleftheroupoleos pays €245 in communal fees every January".

Each Expense record is built from four pieces:

  1. Property — which property this expense belongs to
  2. Expense Line Type — what the expense is (e.g. Property Manager, Communal Fees 1)  →  becomes the row label in the P&L
  3. Expense Type — when it's paid (e.g. Monthly, June, Quarterly)  →  controls which months the amount is counted
  4. Expense Amount — how much (in euros) is paid per active month
Two flavours of Expense record

Most Expenses are standard — one record per property, captured manually. But some are Pro-Rata — one bill split automatically across multiple properties.

  • Standard Expense — e.g. each property pays its own electricity bill at its own amount. Use the Add / Edit (Standard) tab.
  • Pro-Rata Expense — e.g. €3,000 audit fee covers the whole Cyprus portfolio and gets split proportionally across all Cyprus properties. Use the Pro-Rata Capture Flow tab.

Which flow you get is determined by the Expense Line Type you pick — if it has Pro-Rata = Yes, the property selection panel appears automatically.

A worked example

Looking at the table now — Eleftheroupoleos has 8 Expense records, including:

  • Property Manager / Monthly / €52  →  €52 every month, all year
  • Communal Fees 1 / January / €245  →  €245 once per year, in January
  • Communal Fees 2 / July / €210  →  €210 once per year, in July
  • Financials (Cyprus) / June / €293  →  this property's pro-rata share of the annual Cyprus audit fee, paid in June
Where this fits

This is the final piece of the three-part Expense configuration:

  1. Expense Types — when the expense is paid (the months pattern)
  2. Expense Line Types — what the expense is called on the P&L (and whether it's Pro-Rata)
  3. Expenses (this page) — the actual records on each property

If you haven't set up Types and Line Types yet, do those first — the dropdowns on the Add Expense form are populated from them.

Permissions: This page is restricted to Superusers.
Reading the Table

Records are grouped by property in collapsible rows — one row per property, with the records hidden inside until you expand. The layout mirrors the Revenues page exactly.

Property header rows
  •  A chevron arrow on the left — right-pointing when collapsed, down-pointing when expanded.
  • The property name.
  • A teal 8 count badge showing how many Expense records that property has.
Expanding and collapsing
  • Click a property header to expand it. The chevron rotates down and the records appear below.
  • Click the same header again to collapse it.
  • Click a different property's header and the previously-open one auto-collapses — only one property can be open at a time.
Inside each property

Records are sorted alphabetically by Expense Line Type, with five columns:

  • Property — the property name (repeated for clarity).
  • Expense Line Type — the category (e.g. Communal Fees 1, Property Manager).
  • Expense Type — the months pattern (e.g. Monthly, January, Quarterly).
  • Expense Amount — the euro amount per active month, formatted with thousand separators (e.g. € 245, € 1,250).
  • Details — an Edit button to modify that record.
Properties with no Expense records don't appear here. If a property is missing from the list, it currently contributes €0 to the Expenses side of the P&L — click Add New to start populating it.
Adding a Standard Expense

"Standard" means a normal property-specific expense, where each property has its own bill at its own amount — e.g. each property pays its own electricity charge.

Click Add New in the top-right to open the Add Expense form. Four fields in a row:

  1. Property — dropdown of all properties. Pick the one this expense belongs to.
  2. Expense Line Type — dropdown populated from Expense Line Types (e.g. Property Manager, Electricity, Cleaning Costs). Pick a non-Pro-Rata Line Type for the standard flow.
  3. Expense Type — dropdown populated from Expense Types (e.g. Monthly, Quarterly, June).
  4. Expense Amount — the euro amount paid per active month.

Click Save in the top-right and the new record appears in the property's group on the listing page.

The amount is per active month, not per year. If a property pays €52 in monthly Property Manager fees, enter 52 — not 624. The system multiplies by the months your chosen Type marks as active. So €52 paired with Monthly = €624/year, but €245 paired with January = €245/year (one payment).
What if I pick a Pro-Rata Line Type by accident?

If you select a Line Type with Pro-Rata = Yes, the form changes — the Expense Amount becomes auto-filled and locked, and a property selection panel appears below. That's the Pro-Rata flow; switch to the next tab for the full walk-through, or just change the Line Type back to a non-Pro-Rata one.

Editing a Standard Expense

Expand the property's row, then click the Edit button on the relevant record. The form is identical to the Add form, with all four fields pre-filled. Update what you need and click Save.

Edits affect the P&L immediately — including history. Expense records aren't dated — they describe an ongoing pattern. Changing the amount from €52 to €60 instantly recalculates the P&L for every month, every year, including past periods.
Changing the Expense Type clears unused months. If you switch from Monthly to January, the system wipes the amounts from Feb–Dec and only retains January. This keeps the data clean but is irreversible without a manual re-edit.
The Pro-Rata Capture Flow

When you pick an Expense Line Type that has Pro-Rata = Yes, the form switches into a different mode designed to split one bill across multiple properties. Here's the full step-by-step flow.

Step 1 — Open the Add or Edit form

From the listing page, click Add New to capture a new pro-rata bill, or click Edit on an existing pro-rata record to revise the distribution.

Step 2 — Select the four standard fields
  • Property — the property you're capturing the expense for. This will be the "anchor" property in the distribution and cannot be removed from it.
  • Expense Line Type — pick a Pro-Rata Line Type (e.g. Financials (Cyprus)). As soon as you pick it, the form changes.
  • Expense Type — the months pattern for when the bill is paid (e.g. June for an annual audit invoice in June).
  • Expense Amount — auto-filled with the Pro-Rata Amount from the Line Type and locked / greyed out. You cannot override this here — if the bill amount has changed, edit the Line Type's Pro-Rata Amount first, then come back.
Step 3 — The property selection panel appears

A new section titled Select Properties for Pro-Rata Distribution appears below the four fields, with:

  • A Country quick-filter dropdown ("Select Based on Country") — choosing a country auto-ticks every property in that country in one action.
  • A scrollable list of every property, each with a checkbox and the property's Current Value shown in parentheses (e.g. Apolloneon - Demetri (€200,000)).
  • The anchor property is auto-checked and locked — you can't un-tick it because you're capturing the expense for it.

Tick every property the bill should cover. You can:

  • Use the Country filter as a shortcut to tick all (e.g.) Cyprus properties at once
  • Then individually un-tick any that shouldn't be included
  • Manually tick individual properties from other countries if the bill spans them
Step 4 — Calculate Pro-Rata Amounts

Once your selection is made, click the Calculate Pro-Rata Amounts button (sits next to the property panel). This opens the Pro-Rata Expense Preview modal showing exactly what will happen if you save.

Step 5 — Review the Preview modal

The Preview displays:

  • Total Pro-Rata Amount at the top (e.g. €3,000)
  • Selected Properties count (e.g. 10)
  • A per-property table with four columns: Property — Current Value — Share % — Amount
  • Cancel — closes the modal without making any changes; you stay on the form so you can adjust selections
  • Confirm & Update — commits the distribution

The percentages always sum to 100%. The amounts always sum to the Total. Use this preview to sanity-check that the split feels right before committing.

Step 6 — Confirm & Update

Clicking Confirm & Update commits the changes:

  • For properties without an existing Expense for this Line Type → a new record is created
  • For properties with an existing Expense for this Line Type → the existing record is updated with the new amount
  • For properties that were previously included but are now un-ticked (Edit mode only) → their Expense records are removed as part of the recalculation

You're then redirected back to the Expenses listing page with a success message.

What's different in Edit mode

When you click Edit on an existing pro-rata Expense record:

  • The form opens with all previously-included properties pre-ticked — not just the anchor. So if a bill currently spans 10 properties, all 10 checkboxes are already checked when Edit opens. You only touch the ones you want to change.
  • The anchor property (the one you opened Edit on) is locked-in as before
  • You can add new properties to the distribution by ticking them, or remove existing ones by un-ticking them
  • You can change the Property, Expense Type, or Line Type dropdowns at the top — but bear in mind that changing the Line Type can take you out of pro-rata mode entirely
  • On Confirm & Update, the system deletes all original pro-rata records for this Line Type+Type combination and recreates them based on the new selection. This is how it cleanly handles additions, removals, and amount changes in one operation.
This is how the cascade works. One Calculate & Confirm cycle on any one Expense record refreshes the entire Line Type's distribution across all linked properties. You don't need to visit each property individually.
Practical Tips
Setup & entry
  • Set up Configuration first. Expense Types and Expense Line Types must exist before you can create an Expense record. If you're starting from scratch, build out the 12 single-month Types (January, February, …), the recurring Types (Monthly, Quarterly), and your Line Types before coming here.
  • One record per (Line Type + Type) combo per property. If a property has Property Manager fees of €52/month and €245 of Communal Fees in January, those are two separate records — one for each combination of Line Type and Type. Don't try to merge them.
  • Enter the per-month amount, not the annual. €52 monthly Property Manager fees go in as 52. €245 annual Communal Fees in January go in as 245. The Type handles the multiplication based on which months are flagged.
  • Match the Type carefully. The wrong Type produces a P&L that doesn't match reality. If utilities are billed Mar/Jun/Sep/Dec, use a Type with exactly those four months flagged — not Quarterly (which is Jan/Apr/Jul/Oct).
Working with Pro-Rata
  • The Line Type decides the flow. Pro-Rata isn't a checkbox on the Expense record — it's a property of the Line Type. Pick a Pro-Rata Line Type and the property panel appears automatically.
  • Always review the Preview before clicking Confirm & Update. The Preview modal is your last chance to catch a wrong selection before the cascade runs. Check the property list, check the share percentages, check the totals.
  • Use the Country filter as a starting point, not an end point. Click Cyprus to tick all Cyprus properties at once, then un-tick any that shouldn't be included (e.g. a Cyprus property that's in renovation and not yet generating expenses).
  • To update an existing pro-rata distribution, edit any one of the linked records. Open Eleftheroupoleos's Financials (Cyprus) record — any change you make and confirm cascades to all 10 (or however many) properties using that Line Type. You don't need to edit each property's record individually.
  • Pro-Rata Amount changes are handled on the Line Type page — with a live preview. If the total bill has shifted (e.g. €3,000 → €3,500), edit the Pro-Rata Amount on the Line Type and click Save. A preview modal opens showing every linked Expense record's old/new/Δ per property. Confirming with Save & Recalculate All saves the Line Type and cascades the new distribution to every linked record in one atomic operation. No separate Calculate-Confirm trip is needed anymore.
  • Current Value changes on the Property Valuations page also cascade automatically. When you edit a property's Current Value on the Valuations report, the system checks if that property is in any Pro-Rata distributions. If so, a preview modal opens showing every affected distribution (collapsible, one per Line Type) with the per-property ripple effect. Confirming commits the valuation change and recalculates every Pro-Rata Expense touching that property in one operation.
  • When a new property joins the portfolio, add it to existing pro-rata distributions. The new property won't auto-appear in existing pro-rata records. Open any one of the existing pro-rata Expense records, tick the new property in the panel, and re-calculate.
General awareness
  • Expense records aren't dated. They describe an ongoing pattern, not a transaction on a specific date. Changing the amount today rewrites the P&L for past months too.
  • Check the count badge as a sanity flag. If a property normally has 8 records and now shows 7, something's been deleted. Open it and verify nothing important is missing.
  • Properties with no records don't appear in the listing. A missing property = €0 contribution to the Expenses side of the P&L. Usually a bug to fix, not a feature.
  • If a P&L expense figure looks wrong, start here. Every budgeted expense on the P&L is calculated from the records on this page. Expand the relevant property and check.

the last page rules that outranked base, and a third name for a field

The component round removed page-local copies base already beat. Those
deletions could not change anything: base's stylesheet sits after the
content block, so on equal specificity it had already won.

A COMPOUND RULE IS NOT EQUAL. `.form-field .form-control` is two classes
where base's is one, and specificity is settled before document order - so
it wins wherever it sits, however recently base was written. Every
deletion in this round therefore DOES change a page. This is where the
last screens actually adopt the standard, and the first component round
that cannot claim to be invisible.

THE THIRD NAME FOR A FIELD

The Financials expense screens wrapped their fields in .form-field. The
rest of the system uses .form-group, which is what base declares and what
section 3.6 is written in. That third name is the whole reason base's
field rule never reached those screens: every rule they needed had to be
written again, scoped to the wrapper, and each one then outranked base for
good. The wrapper is renamed rather than worked around.

THE RED FOCUS RING

finance_expense_add and finance_expense_edit declared

    .form-field .form-control:focus   border-color #dc3545

so every field on those screens turned RED when clicked into. #dc3545 is
--alv-bad: the colour this system uses for errors and overdue money.
Nobody chose red focus; it arrived, and stayed because no rule said
otherwise. Settled 17 Sep: not deliberate. It goes, and those fields take
base's accent ring like every other screen.

WHAT IS KEPT, AND NAMED WITH THE REASON

.vat-input-wrap .form-control keeps its padding-right, which makes room
for the VAT suffix and which base never claimed. .prorata-panel
.form-section-title keeps its dark red, because base could claim the
property but the value carries meaning of its own. A named exception with
a reason is a standard; an unnamed one is drift.

REPORTED, NOT TOUCHED: six pages title their panel with an h2 inside
.form-card rather than with .form-section-title, and one styles a
Bootstrap card body. Two ways to title a panel is a round of its own.

I CLASSIFIED BY SUBSTRING AND NEARLY DELETED A CARD BODY

The first classifier asked whether a component's name appeared anywhere in
the selector. `.form-card .card-body` contains one and styles something
base has never heard of, so it was marked a duplicate - and deleting it
would have taken the padding off a card body on a signed-off page. It
classifies by TARGET now: the last simple selector, which is the element
the rule actually styles.

The same classifier called `.form-group label` "something base does not
own". base declares exactly that selector. It is not compound at all.

AND A REPORT THAT COUNTED 651 RULES

The suite's report of rules targeting things base does not own printed
651 - which is every compound selector in the repo, .page-header h1 and
.filter-label i included, because I dropped the guard limiting it to these
components. A report with that number in it is not a report about
anything. It is 7.

THE FOCUS CHECK COULD NOT FAIL, AND FINDING OUT WHY TOOK THE LONGEST

Section 3 renders each screen and reads the control back, including the
focus state - which is how the red ring was found and which nothing
static can see. The first version read the computed border colour
immediately after focusing, and it passed no matter what the focus rule
said. The proof was a sabotage: re-adding the red ring was caught by the
static check and ignored by the rendered one.

The cause is base's own `transition: border-color 0.15s ease`. The value
read at 0ms is still the RESTING colour; the animation has barely started.
Measured across time it goes #e3e8ea, then #68aab3 at 50ms, then #0e7c8b
by 150ms. An injected !important rule at ID specificity appeared to lose
for exactly the same reason, which should have been the clue and was not -
I spent a while concluding the focus ring was dead system-wide and about
to report an accessibility fault. IT WORKS. The fixture now disables
transitions, and the check has a control requiring the focused colour to
DIFFER from the resting one, so it cannot quietly go back to measuring
nothing.

A rendered check has to stop the clock or wait for it. That is the lesson
and it applies to every suite in this repo that measures a colour.

VERIFIED: 10 checks, sabotaged three ways - re-add the red ring, re-add a
duplicate rule, put the third wrapper name back - and the red-ring
sabotage is now caught by BOTH the static and the rendered check. Every
suite run before and after with full output compared: four differ, all
explained. test_form_components counts two more surviving bare rules
because the renamed wrapper's label rule is now spelled .form-group label;
test_label_bold reports the same rule under its new name; test_deeper_teal
counts three fewer accent literals, which went with the deleted rules.

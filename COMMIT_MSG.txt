Entry sections push 1: one section component, and base takes over the phone

This system had SEVEN ways to say "this is a section" - form-section-title,
section-title, form-section-heading, pi-section-title, lines-title, a bare
<h5> and h5.mb-0 - and base declared exactly one of them. Push 1 takes every
screen that already HAS sections and puts them on that one. It moves no
fields; that is pushes 2 and 3.

On the way it found something bigger than the sections. iOS Safari zooms the
page whenever a focused input is under 16px, and base sets .form-control to
14px. SIXTY-TWO PAGES had each written their own guard against that, in
selector dialects that include `.form-group .form-control`,
`input[type="text"].form-control`, `.modal-body input[type="number"]`,
`.line-input` and `.expense-form .form-control`. Same shape as the
.form-control rule itself before the form-components round: base reached a
class name and declared none of the behaviour. Base owns it now, in one rule.

WHAT THE MEASUREMENT CHANGED

The mobile rule proposed before measuring had three declarations. Two were
wrong and only the browser said so.

  * Dropping .form-card's margin to 16px made the gap BETWEEN panels equal
    to the 16px gap between fields INSIDE one. The grouping this round
    exists to create, erased by the round's own CSS.
  * Shrinking the title to 15px was unnecessary - at 375px it has 293px to
    draw in and was never clipped - and would have left it one pixel above
    the 14px labels.

What survived is the padding, which buys 293px -> 313px of field width at
375 wide, and the guard.

AND THE GUARD FIXED SOMETHING IT WAS NOT AIMED AT. A control sized so iOS
will not zoom is also a control big enough to hit: 16px inside
.form-control's 9px padding and 2px border renders 46px, over the 44px tap
target it was failing at 41px. On the desktop nothing changed - 14px gives
43px, measured on the deploy machine - so that round is still owed, just no
longer owed on a phone. (The suite REPORTS both numbers rather than
asserting them: control height depends on the font the machine has, and a
threshold that moves with the renderer is not a threshold.)

FIVE THINGS CAUGHT BEFORE ANYTHING SHIPPED - THE LAST BY THE GATE

  1. `\bform-section\b` MATCHES INSIDE `form-section-title`. A hyphen is a
     non-word character and \b is happy to sit on it, so renaming
     .form-section to .form-card turned create_meal_plan's two new headings
     into class="form-card-title". The self-check found it: 0 component
     headings where 2 were expected. A class name ends where a character
     that cannot appear in one begins, and a hyphen can.
  2. A COMMENT IN FRONT OF @media HIDES IT. Every rule inside a media query
     was invisible to a walk that tested sel.startswith('@'), because the
     text handed to it began `/* Card padding */`. split_rules not recursing
     into @media has now been a bug in four rounds, in four shapes.
  3. THE PANEL WENT ROUND THE WRONG HEADING. customer_invoice_form already
     carried a component heading - stage D put it on the Customer panel - so
     `text.find(the component)` opened a second .form-card inside the first
     and left Invoice Lines outside both.
  4. RETARGETING A RULE CAN MAKE IT VISIBLE TO A GUARD IT WAS HIDING FROM.
     `.notification-card.is-collapsible > h5 { margin-bottom: 0 }` passed
     every check while it named a TAG, because base does not own h5. Pointed
     at the component it became a compound rule whose every property base
     already declares, and test_compound_rules.py stopped the push for it.
     It was dead weight before this round too - the rule above it already
     sets margin-bottom: 0 on every card, collapsible or not - so it is
     deleted rather than excused. The gate found this one; the round's own
     self-checks did not.
  5. A SELECTOR SAYS WHAT A RULE IS CALLED; ONLY THE BODY SAYS WHAT IT DOES.
     `.form-section-heading small` looked harmless in the dry run. Its body
     was `font-weight: 400`, and base declared nothing like it, so deleting
     it would have rendered edit_asset's "(up to 5 per asset - JPG/PNG, 5MB
     each)" at full heading weight. base gains the rule instead. The tool
     now has --verbose and it should be used before believing a dry run.

ONE HEADING IN THIS ROUND IS A CONTROL

notification_settings' section title opens and closes its card. Six CSS
rules selected `.notification-card > h5` and one line of JavaScript did
card.querySelector('h5'). Both now name the component, which is the right
selector either way: what makes that element the trigger is that it is the
card's title, not its tag. .notification-card keeps its name because it also
carries the open/closed state; only its appearance moved onto base's panel.

TWO PANELS COULD NOT BE SPLIT, AND THE ROUND SAYS SO

The rule agreed for this round is "a section is a panel". On edit_asset and
property_assets the <form> opens INSIDE the panel, so closing it at a
section boundary would cut the form in half. Those two keep one panel with
titled sections inside, exactly as suppliers_add does, and their <hr> goes
because the component's own accent rule is the divider now.

ONE WORDING CHANGE, NAMED

preview_imported_recipe's Cooking Calculator heading loses a fire emoji,
because fa-fire now does that job. The emoji is in four other places on that
page and none of them is this round's business. The suite names this one
exception rather than permitting drift in general.

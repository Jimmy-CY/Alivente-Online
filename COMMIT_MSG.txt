ONE RULE DECIDES WHICH SHAPE A SCREEN CAN HAVE

A screen gets panel-per-section IF AND ONLY IF its <form> opens BEFORE its
panel. If the form opens inside the panel, closing the panel at a section
boundary cuts the form in half. That is one measurement per file and it
replaces arguing per screen.

THE MODEL SCREEN DID NOT STACK ON A PHONE

customer_invoice_form is the screen this whole standardisation is measured
against, and it was the only entry screen in the system whose fields stayed
side by side on a phone. It used Bootstrap's UNPREFIXED column classes -
col-7, col-5, col-6, col-8, col-4 - which hold their percentage at every
width, where col-md-* stacks below 768px.

    at 375 wide, before   Customer Name and Customer ID   152px, side by side
    at 375 wide, after                                    313px, stacked

Seven class names. The desktop is untouched: col-md-6 and col-6 are
identical at and above 768px. col-12 is left alone - full width at every
size, never part of the fault.

THE WIDTH RULE

A row whose membership does not change keeps its widths untouched. A row
that is rebuilt is three across at col-md-4, or four across at col-md-3
where a panel holds exactly four fields. col-md-3 is the only width this
round writes: measured, 313px per field at 375 wide and one line of four at
1280.

THE FAULT THAT MATTERS MOST, AND IT WAS THIS ROUND'S OWN

The first draft SILENTLY DELETED TWO HIDDEN INPUTS. properties_add keeps

    <!-- Hidden fields for coordinates -->
    <input type="hidden" name="prop_latitude"  id="prop_latitude">
    <input type="hidden" name="prop_longitude" id="prop_longitude">

directly inside the panel, above the first row. The rebuild emitted the
panel from its row blocks alone and discarded both - and THE TOOL'S OWN
SELF-CHECK DID NOT SEE IT, because that check filtered hidden inputs out
before counting. The suite caught it: 22 controls before, 20 after.

Two fixes, both permanent:

  * The region now carries everything that is not a block, AND PLACES IT
    WHERE IT BELONGS. Content before the first row goes before the first
    panel; content between rows is glued to the row that FOLLOWS it, so a
    comment stays with what it comments; content after the last row goes in
    front of the panel this round keeps. Anything that is not whitespace, a
    comment or a control is structural, and the run stops rather than
    guessing where it goes.
  * A HIDDEN INPUT IS DATA. The self-check no longer excludes it. Only
    controls that DO something rather than SAY something are left out.

AND TWO MORE OF THE SAME KIND

  * THE INVARIANT IS RELATIVE ORDER, NOT ABSOLUTE POSITION. The first
    version compared each field's index and flagged nineteen fields across
    four screens that had not moved relative to anything - they had simply
    been stepped over by something that did.
  * A FORM CAN VANISH WITHOUT CHANGING A BALANCE. Rebuilding a panel that
    CONTAINS the <form> deletes the open tag and its close together, so the
    delta stays at zero and the check passes a file with no form in it. The
    first draft did that to customer_form, and the balance check passed it.
    The suite counts form tags now, and customer_form takes titles only.

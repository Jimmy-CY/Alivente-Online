Entry sections, corrected: a section title is not a grid cell, a modal
header is already a title, and asset_detail was never reached

Three faults, all found by LOOKING AT THE SCREENS rather than by any check.
Every suite passed on all three, and that is the part worth recording.

1. A SECTION TITLE IS NOT A GRID CELL - 7 screens

Six screens lay their fields out in

    .form-grid { display: grid; grid-template-columns: 1fr 1fr; }

and customer_invoice_form puts its invoice date and VAT rate in

    .settings-row { display: flex; }

Push 2 put the title INSIDE those containers, so it became an ITEM. It took
one cell. Its accent rule stopped halfway across the panel. The first field
sat BESIDE the heading instead of under it.

    finance_revenue_add / _edit
    finance_revenue_line_types_add / _edit
    finance_expense_line_types_add / _edit
    customer_invoice_form

EVERY CHECK PASSED ON ALL SEVEN. They all asked whether the title was
there; not one asked WHERE. The suite now asks - section 15 walks a tag
stack and fails on any section title whose parent is a grid or flex
container.

WHY NOT FIX IT IN base. `.form-section-title { grid-column: 1 / -1 }` would
make the component span wherever it lands, and it was tempting.
preview_imported_recipe's Cooking Calculator heading sits inside
`.cooking-calc-toggle { display: flex }` ON PURPOSE, beside a chevron, and
notification_settings' heading IS a flex container rather than an item in
one. A blanket rule would break the two places the arrangement is
deliberate. The structural fix is precise; the global one is a guess that
happens to be right six times out of seven.

2. A MODAL HEADER IS ALREADY A TITLE - 3 screens

"A modal body is already a panel" was right, and it was half the rule. Push
3 gave three single-section modals a title that repeats the header the modal
already carries:

    view_meal_plan                 header "Duplicate Meal Plan"
                                   title  "Duplicate Meal Plan"
    household_member_management    header "Add Person" / "Edit Person"
                                   title  "Person"
    celebration_management         header "Add Contact"
                                   title  "Contact"

The first repeats it word for word. A title on a one-section modal has
nothing to add: it says the heading again, one line lower. All three are
gone.

A modal with MORE than one section keeps its titles, because there they do
the dividing - passport_management keeps Document, Validity and File, and
celebration_management's Add Event keeps Event and Notifications.

3. asset_detail WAS NEVER REACHED

It was in the first survey with "Maintenance Record" proposed and it was
lost between that document and push 1. No reason was recorded because there
was not one. Its two modals carry six fields each in one undivided run.

It does NOT get "Maintenance Record" - that is fault 2, and the modal header
already says it. It gets the split the six fields actually have:

    Work              Date, Type, Description
    Provider & Cost   Service Provider, Cost, Invoice/Receipt

on both the Add and the Edit modal. The two modals hold the same field
names, so each is found by its own header rather than by a first match -
otherwise every title lands in the first one and none in the second.

WHAT THIS ROUND DOES NOT DO

It moves no field. Every control on every screen it touches is in the same
order afterwards, and the self-check fails the run if one is not.

PROOF

    test_entry_sections.py    232 passed, 0 failed, 0 skipped

Sabotage-checked: putting a title back inside .form-grid fails section 15
by name, and removing one asset_detail title fails its count.

THE LESSON, WRITTEN DOWN

A check that asks whether something EXISTS is not a check that it is in the
right PLACE. Seven screens carried a heading that every suite could see and
none could locate. The rendered sections of this suite measure size, colour
and stacking; they render a FIXTURE, which is built correctly by
construction, so they could never have caught this. What caught it was
opening the page.
